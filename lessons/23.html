1. この講義の位置付けと到達目標

第12〜14講ではIPアドレスやサブネットを、第20講ではNAT/NAPTを、第21〜22講ではDNSを学習しました。PCが通信するときにIPアドレス、サブネットマスク、デフォルトゲートウェイ、DNSサーバなどの設定情報を利用することを説明してきました。しかし、PCを新しくネットワークに接続したとき、これらの情報はどこから取得するのでしょうか。企業内に数千台のPCがある場合、管理者が1台ずつIPアドレスを設定するのは現実的ではありません。設定ミスによって同じIPアドレスを複数台に割り当ててしまう可能性もあります。この問題を解決する仕組みが、DHCP（Dynamic Host Configuration Protocol）です。DHCPはネットワーク設定を自動化する便利なプロトコルですが、攻撃者が偽の設定情報を配布する入口にもなります。

本講義の到達目標は、DHCPの役割とDNS・ARP・ルーティングとの関係、DORAの通信順序、UDPポート67・68、ブロードキャスト、DHCPリレーエージェント、リース、不正DHCPサーバ、DHCP Starvation、DHCP Snooping、設定とログの読み方を説明できることです。

参考書：『徹底攻略 情報処理安全確保支援士教科書 令和7年度版』第3章「ネットワーク基礎技術」3-3-4「その他のアプリケーションプロトコル」pp.230〜233（先行するチャット講義で確認された範囲）。不正DHCPサーバ、Starvation、Snooping、ログ分析は講師補足です。IPA過去問全体での出題頻度は未検証です。

優先度範囲
A：必須4段階、ブロードキャスト、ポート番号、リレー、リース、不正サーバ、Snooping、ログ・対策
B：理解補助設定の背景、ARP、リース更新、競合
C：発展DHCPv6、Option 82、製品固有のコマンド

2. DHCPとは何か【A：必須】

DHCPはネットワークに接続した機器に対して、通信に必要な設定情報を自動的に配布するプロトコルです。

設定情報役割例
IPアドレス自分自身のアドレス192.168.10.101
サブネットマスク同一ネットワークの判断255.255.255.0
デフォルトゲートウェイ別ネットワークへの転送先192.168.10.1
DNSサーバドメイン名の名前解決192.168.10.53

IPアドレスが正しくてもゲートウェイが誤っていれば別ネットワークに接続できないことがあります。DNSサーバが誤っていればIPアドレス直接指定の通信は成功しても、ドメイン名指定では失敗することがあります。

DHCPクライアントはPCやスマートフォンなど設定を受け取る側、DHCPサーバは配布する側です。

ネットワーク：192.168.10.0/24
配布可能IP：192.168.10.100 ～ 192.168.10.199
サブネットマスク：255.255.255.0
デフォルトゲートウェイ：192.168.10.1
DNSサーバ：192.168.10.53
リース期間：8時間

DHCPは設定情報を配布する仕組みであり、インターネット接続やDNS名前解決を自ら実行するわけではありません。

3. なぜDHCPはブロードキャストを使うのか【A：必須】

ネットワークに接続した直後のPCは、自分のIPアドレスもDHCPサーバのIPアドレスも知らない場合があります。特定の宛先を指定できないため、初期のDHCPDISCOVERでは同じブロードキャストドメインに呼びかけます。

送信元IPアドレス：0.0.0.0
宛先IPアドレス　：255.255.255.255
送信元UDPポート：68
宛先UDPポート　：67

0.0.0.0はまだ利用可能なIPアドレスを取得していない状態を表し、255.255.255.255は限定ブロードキャストアドレスです。通常、ルータはこのブロードキャストを別ネットワークへそのまま転送しません。別サブネットのDHCPサーバを使うにはリレーエージェントが必要です。

まだサブネットマスクも知らないので、最初から192.168.10.255を使うのではありません。参考書p.232の令和2年10月SC午前Ⅱ問題でも関連事項が扱われています。

4. DHCPの4段階通信：DORA【A：必須】

4-1. DHCPDISCOVER：発見

クライアントが「DHCPサーバはありますか。利用できるIPアドレスを教えてください」と問い合わせる段階です。通常ブロードキャストします。

4-2. DHCPOFFER：提供

サーバがIPアドレス、サブネット、ゲートウェイ、DNS、リース期間などを提案します。OFFERを受け取った時点では割当てはまだ確定しません。複数のサーバからOFFERが届くこともあります。

4-3. DHCPREQUEST：要求

クライアントが提案を選んで割当てを要求します。初期割当てでは一般にブロードキャストし、選ばれなかったサーバにも選択結果が分かるようにします。選択したサーバの識別情報と要求IPアドレスなどが含まれます。

4-4. DHCPACK：確認応答

サーバが要求を承認してリースが成立します。ただし競合検出時には利用を開始しないことがあり、要求を認めない場合はDHCPNAKが返されることもあります。

メッセージ送信者意味
DISCOVERクライアントサーバを探す
OFFERサーバアドレスを提案
REQUESTクライアント割当てを要求
ACKサーバ承認する

注意：参考書ではOFFERとACKをユニキャストとして説明していますが、実際のDHCPv4ではブロードキャストされる場合もあります。試験では設問の条件を優先します。

5. DHCPで使われるUDPポート【A：必須】

DHCPv4はUDPを使い、サーバはUDP 67、クライアントはUDP 68を利用します。

0.0.0.0:68 → 255.255.255.255:67

TCPでは一般に相手のIPアドレスを指定して接続を確立する必要がありますが、初期DHCPでは自分のIPもサーバのIPも分からない場合があります。UDPとブロードキャストを組み合わせることで通信します。ただしUDP通信が必ずブロードキャストになるわけではありません。

6. DHCPリレーエージェント【A：必須】

企業ネットワークでは部署ごとにVLANやサブネットを分けます。

クライアントのブロードキャストは通常ルータを越えません。リレーエージェントが受信してサーバへ転送し、応答をクライアントに届けます。

DHCPv4のgiaddr（gateway IP address）フィールドにクライアント側ネットワークの情報を設定でき、サーバは適切なアドレスプールを選べます。例えばgiaddrが192.168.10.1なら、192.168.10.0/24用のプールを選択できます。

VLAN分割後にIPアドレスを取得できなくなった場合は、リレー設定、サーバ到達性、サブネット用プール、FW/ACLによる必要通信の遮断を確認します。故障と決めつけず、どの段階で通信が止まったかを調べます。

7. IPアドレスの割当てとリース【A：必須】

DHCPのアドレスは原則として永久所有ではなく、一定期間の使用権であるリースとして管理されます。例えば100個のアドレスを一時利用者に永久に予約し続けると、未接続の機器によってアドレスが枯渇します。リース期限を設けることで再利用できます。PCの電源を切った瞬間に必ず解放されるわけではなく、DHCPRELEASEが送られない場合はサーバが期限に従って管理します。

タイミング動作
T1：通常50%元のサーバに更新要求
T2：通常87.5%利用可能なサーバへ再要求
リース満了更新できなければ原則使用停止

8時間リースなら通常約4時間後に更新を始め、約7時間後に再バインドを試みます。更新時に毎回DISCOVERから始めるわけではなく、通常はDHCPREQUESTを使用します。

MACアドレスなどに基づくDHCP予約によって同じアドレスを割り当てることもできます。ただしMACアドレスは偽装可能であり、予約だけで端末の正当性は保証できません。

8. DHCPとARPの関係【B：理解補助】

DHCPサーバが提案したIPアドレスを、手動設定の別端末が既に使っている場合があります。競合すると通信が不安定になります。クライアントはARP Probeなどで競合を調べ、競合が見つかればDHCPDECLINEでサーバに通知することがあります。DHCPはIP設定の取得、ARPは同一リンクでのIP/MAC対応確認や競合検出という別の役割を持ちます。

9. DHCPのセキュリティ上の問題【A：必須】

通常のDHCPv4のやり取り自体には、サーバが正規の管理者によるものかを強固に確認する仕組みがありません。攻撃者が同一ネットワークに不正サーバを接続すると、偽のIP設定を配布できる可能性があります。特にゲートウェイとDNSサーバを変更できる点が重要です。

10. 不正DHCPサーバによる攻撃【A：必須】

正規サーバの配布設定
IPアドレス：192.168.10.101
ゲートウェイ：192.168.10.1
DNSサーバ：192.168.10.53

不正サーバの配布設定
IPアドレス：192.168.10.101
ゲートウェイ：192.168.10.200
DNSサーバ：192.168.10.200

攻撃者が192.168.10.200を管理しているとします。PCのDISCOVERに正規・不正の両サーバがOFFERを返し、PCが不正サーバの提案を選択すると、偽のゲートウェイやDNSが設定されます。先にOFFERを返したサーバが必ず選ばれるわけではありません。

偽ゲートウェイによる誘導

外部宛通信を攻撃者の機器に向け、そこから正規ルータへ転送すれば中間者攻撃の足掛かりになります。ただしHTTPSの適切な暗号化・証明書検証があれば、経路上にいるだけで内容を自由に復号できるわけではありません。

偽DNSサーバによる誘導

攻撃者が管理するDNSサーバを配布すると、ドメイン名の問合せに偽サイトのIPアドレスを返せます。DNSキャッシュポイズニングはキャッシュの内容を不正にする攻撃ですが、こちらはクライアントのDNSサーバ設定を変える攻撃です。原因と対策を混同しないようにします。

11. DHCP Starvation攻撃【A：必須】

DHCP Starvationは正規DHCPサーバの配布可能なIPアドレスを枯渇させる攻撃です。攻撃者が多数の異なるクライアントを装い、サーバがそれらのリースを確保すると、正規PCに配布できるアドレスがなくなります。これは可用性への攻撃です。DISCOVERを大量に送るだけで必ず全アドレスが確保されるわけではなく、サーバ実装やリース成立状況によります。正規サーバを妨害した後に不正DHCPサーバで偽設定を配る組合せも考えられます。

12. DHCP Snoopingによる防御【A：必須】

L2スイッチのDHCP SnoopingはDHCPメッセージを監視し、不正サーバからの応答を遮断します。

Trustedポートは正規サーバの応答が到来してよいポート、Untrustedポートは一般PCなどの接続ポートで、サーバ応答を原則受け入れません。Trustedを誤ると正規応答を遮断したり不正応答を許したりします。科目Bでは機能名だけでなく、どのポートをTrusted/Untrustedにするかを記述します。

脅威対策
不正DHCPサーバSnoopingによる不正サーバ応答の遮断
DHCP StarvationDHCP要求レート制限、接続端末数の制限
不正IP/MAC利用バインディング情報とIP Source Guard等の連携

Snooping単独ですべてのIP詐称やDNS攻撃を防ぐわけではありません。

13. DHCP Snoopingバインディングテーブル【A：必須】

DHCP Snoopingは正規の割当て情報を記録できます。

IPアドレスMACアドレスVLANポート
192.168.10.101AA:BB:CC:00:00:0110Gi1/0/1
192.168.10.102AA:BB:CC:00:00:0210Gi1/0/2

IP Source Guardはポートで許可された送信元IPアドレスを検査し、IP詐称を抑制します。Dynamic ARP Inspection（DAI）はARPパケットのIP/MAC対応を検査し、ARPを利用した不正な対応付けを防ぎます。いずれもDHCP Snoopingのバインディング情報を参照できます。静的IP端末にはDHCPバインディングがないため別途設定が必要になる場合があります。

14. DHCP関連の設定とログの読み方【A：必須】

以下は理解用の架空のログ・設定で、特定製品のコマンド構文ではありません。

例1：リレー未設定

VLAN 10：192.168.10.0/24
DHCPサーバ：192.168.20.10
Router VLAN10 Interface:
  IP Address: 192.168.10.1/24
  DHCP Relay: Disabled

DHCPサーバが別サブネットなのにリレーが無効であり、DISCOVERをサーバに届ける仕組みがありません。対策はクライアント側のL3機器で正規サーバを転送先とするリレーを設定することです。

例2：不正サーバ応答の検出

10:15:21  VLAN 10  Port Gi1/0/8
          DHCP OFFER detected
10:15:21  Source MAC: 00:11:22:33:44:55
10:15:21  DHCP Server Identifier: 192.168.10.200
10:15:21  Action: Dropped by DHCP Snooping
          Reason: Untrusted port

UntrustedポートからDHCP OFFERが届いたため遮断されています。ただし攻撃者の意図まで断定はできず、家庭用ルータの誤接続なども考えられます。

例3：アドレス枯渇

DHCP Pool: VLAN10
Available addresses: 0
Active leases: 100
Pool capacity: 100
New client request: No available address

新規端末に割り当てられるアドレスがありません。しかし、これだけでStarvation攻撃とは断定できません。短時間の大量リースや同一ポートからの多数の異なるクライアント識別情報などを調べます。

例4：DNSサーバのみ想定外

IP Address:       192.168.10.101
Subnet Mask:      255.255.255.0
Default Gateway:  192.168.10.1
DNS Server:       192.168.10.200

IPとゲートウェイは正しくてもDNSが想定外なら名前解決が不正誘導される可能性があります。手動設定かDHCP配布かを確認し、DHCP由来なら配布元サーバを調べます。

16. 科目Bでの答案作成ポイント【A：必須】

ケース1：別VLANの端末がIPアドレスを取得できない

不十分：「DHCPの設定が間違っているため。」

改善：「DHCPサーバが別サブネットに存在するが、クライアント側のL3機器にDHCPリレーが設定されておらず、DHCPDISCOVERがサーバに転送されないため。」

ケース2：不正DHCPサーバ対策

不十分：「DHCP Snoopingを設定する。」

改善：「DHCP Snoopingを有効にし、正規DHCPサーバへの接続ポートをTrusted、利用者端末の接続ポートをUntrustedとして、不正なDHCPサーバからの応答を遮断する。」

ケース3：偽DNSサーバ配布

不十分：「DNSが改ざんされるため。」

改善：「不正DHCPサーバが攻撃者のDNSサーバをクライアントへ配布すると、名前解決の問合せ先が変更され、偽サイトのIPアドレスを返されるおそれがあるため。」

ケース4：Starvationの調査

不十分：「IPアドレスが不足しているので攻撃である。」

改善：「短時間に多数の異なるクライアント識別情報でリースが確保され、アドレスプールが枯渇しているため、DHCP Starvationの可能性がある。」

17. 重要事項の総整理と発展学習【A・C】

DHCPはIPアドレスなどの設定を自動配布し、初期割当てはDISCOVER→OFFER→REQUEST→ACKです。初期DISCOVERは送信元0.0.0.0、宛先255.255.255.255のブロードキャストです。別サブネットのサーバにはリレーが必要で、割当てにはリース期間があります。不正サーバによる偽ゲートウェイ・偽DNS配布を防ぐためにDHCP Snoopingで正規サーバの経路だけをTrustedにします。Starvationにはレート制限などを検討します。

発展学習（任意）：DHCPv6とSLAAC、Option 82、DHCPサーバ冗長化、オプション番号の網羅、製品固有の設定コマンド。まずDHCPv4の正常動作と脅威・防御の説明力を優先します。
