2. VPNとは何か【A：必須】

VPN（Virtual Private Network）は、共有ネットワーク上に、仮想的な専用の通信経路を構築する仕組みです。

例えば、本社と支社を接続する場合を考えます。物理的な専用線を敷設しなくても、インターネットを経由して両拠点のネットワークを接続できます。

ただし、インターネットは自社専用の通信設備ではありません。そこで、必要に応じて暗号化や通信相手の認証を組み合わせます。

トンネリングと暗号化は別物

ここは最初に明確にしておきましょう。

トンネリングとは、ある通信データを別の通信形式の中に包んで運ぶことです。暗号化とは、鍵を持たない第三者が通信内容を読み取れないように変換することです。

技術目的
トンネリング仮想的な通信経路を作り、元の通信を運ぶ
暗号化通信内容の機密性を守る
認証接続相手や利用者が正当か確認する
完全性保護通信内容の不正な改ざんを検知する

GREやL2TPは、トンネリングの仕組みを提供しますが、それだけで通信内容を暗号化するわけではありません。

したがって、「トンネルを作ったから盗聴されない」という説明は誤りです。

3. VPNの二つの代表的な利用形態【A：必須】

3-1. 拠点間VPN（Site-to-Site VPN）

本社と支社のVPN装置同士を接続する構成です。

本社のPCが支社のサーバへアクセスすると、通常は次の流れになります。

  1. 本社PCが支社サーバ宛てのIPパケットを送信する。
  2. 本社側VPN装置が、そのパケットをIPsecなどで保護してカプセル化する。
  3. インターネットを通じて支社側VPN装置へ届ける。
  4. 支社側VPN装置が保護を検証し、復号・カプセル化解除を行う。
  5. 元のIPパケットを支社LANへ転送する。

暗号化される区間は通常、両VPN装置の間です。

本社PCから本社VPN装置まで、あるいは支社VPN装置から支社サーバまでの通信が、VPNによって自動的に暗号化されるわけではありません。

これは科目Bで「どの区間で盗聴の危険が残るか」を判断する際に重要です。

3-2. リモートアクセスVPN

在宅勤務者などの端末から、会社のネットワークへ接続する構成です。

リモートアクセスVPNでは、端末にVPNクライアントを導入する方式や、ブラウザから利用する方式などがあります。

ここで注意したいのは、VPNへの接続を認めることと、社内のすべてのシステムへのアクセスを認めることは別だという点です。

VPN接続後も、利用者の権限に応じたアクセス制御が必要です。

4. IPsec-VPNの仕組み【A：必須】

IPsecは、IPパケット単位で通信の暗号化や完全性保護などを実現する技術群です。

IP層で動作するため、特定のWebアプリケーションだけではなく、TCPやUDPなどを使う多様な通信を保護できます。

4-1. ESPとAH

IPsecの代表的なプロトコルはESPとAHです。

項目ESPAH
正式名称Encapsulating Security PayloadAuthentication Header
暗号化対応対応しない
完全性・送信元認証構成に応じて対応対応
主な用途暗号化を伴うVPN暗号化しない認証・完全性保護

実際のVPNでは、一般にESPが中心となります。

重要なのは、ESPという名前だけで「必ずすべての情報が暗号化される」と判断しないことです。暗号化範囲はトランスポートモードとトンネルモードによって異なります。

4-2. トランスポートモードとトンネルモード

トランスポートモード（概念）

元のIPヘッダーESPで保護するペイロード

元のIPヘッダーを維持し、主にIPペイロードを保護します。

トンネルモード（概念）

新しいIPヘッダーESPで保護する元のIPパケット
元IPヘッダー ＋ 元IPペイロード

新しいIPヘッダーを付加し、元のIPパケット全体をトンネル内で保護します。

拠点間IPsec-VPNでは、一般的にトンネルモードを使用します。

例えば、本社PC 10.1.0.10 から支社サーバ 10.2.0.20 へ通信する場合、元のIPパケットにはこの2つのアドレスが含まれます。

トンネルモードでは、それを保護したうえで、外側にVPN装置同士の通信に使うIPヘッダーを付加します。

そのため、インターネット上のルータは外側のIPヘッダーを使って転送できます。一方、元のIPヘッダーはESPによって暗号化される構成であれば、途中の第三者から読み取れません。

試験の典型論点：元のIPヘッダーまで暗号化されるのは、ESPを使ったトンネルモードです。

5. IKEとSA：VPN接続前に何をするのか【A：必須】

IPsecで暗号化通信を始めるには、通信相手と使用する暗号アルゴリズムや鍵などを決める必要があります。

この交渉を担う仕組みがIKE（Internet Key Exchange）です。

SA（Security Association）は、通信を保護するための暗号方式、鍵、相手などに関する取り決めです。

処理を大まかに整理すると、次のようになります。

  1. VPN装置同士が通信を開始する。
  2. IKEで暗号アルゴリズムなどを交渉する。
  3. 通信相手を認証し、鍵を確立する。
  4. IPsecで使用するSAを確立する。
  5. 確立したSAに従い、ESPなどでデータ通信を保護する。

例えば、片方のVPN装置だけが対応する暗号方式を設定していて、もう片方が対応していない場合、SAの確立に失敗する可能性があります。

また、事前共有鍵が一致していない場合も、認証に失敗する原因となります。

IKEv1とIKEv2の違い【B：理解補助】

参考書には、IKEv1のメインモード・アグレッシブモードの説明があります。

一方、現行の構成を考える際には、IKEv2も重要です。IKEv2ではIKEv1とは異なる交換手順を使うため、IKEv1のメインモードとアグレッシブモードを、IKEv2の接続手順として説明してはいけません。

科目A・Bでは、まず「IKEが認証・鍵交換・SA確立に関係する」という役割を確実に理解しましょう。

6. NATとIPsec：NAT-Tの役割【A・B】

第20講で学習したNAT・NAPTを思い出してください。

NAPTは、IPアドレスだけでなくTCPやUDPのポート番号も使って、複数の端末の通信を区別する技術です。

ところが、IPsecのESPは通常のTCPやUDPとは異なり、IPプロトコル番号50を使います。したがって、一般的なNAPTで扱いにくい場合があります。

また、AHはIPヘッダーの一部も完全性保護の対象とするため、NATによるアドレス書換えと相性が悪いという問題があります。

そこで利用されるのが、NAT-T（NAT Traversal）です。

NAT-Tでは、ESPパケットをUDPでカプセル化することで、NAT・NAPTを通過しやすくします。

用途代表的な番号
IKEUDP/500
IPsec NAT-TUDP/4500
ESPIPプロトコル番号50
AHIPプロトコル番号51

ESPの「50」はTCP/50やUDP/50ではありません。 IPヘッダーのプロトコル番号です。

ファイアウォール設定を読む際に、この違いを混同しないようにしてください。

7. SSL-VPN（TLS-VPN）の仕組み【A：必須】

SSL-VPNは、SSL/TLSを利用してVPNを実現する技術です。現在はSSLではなくTLSを使用するため、TLS-VPNとも呼ばれます。

参考書では、ブラウザから利用しやすい点が特徴として説明されています。

ただし、TLS-VPNにも複数の方式があります。

7-1. Webポータル方式

利用者がブラウザでVPNゲートウェイにアクセスし、認証後に社内Webシステムなどを利用する方式です。

例えば、在宅PCのブラウザから社内の勤怠システムへアクセスする場合です。

この方式では、ブラウザだけで利用できる構成がありますが、通常、利用できるアプリケーションの種類には制約があります。

7-2. ポートフォワード方式

特定のアプリケーション通信をVPN経由で転送する方式です。

例えば、端末の特定のローカルポートへの接続を、VPNゲートウェイ経由で社内サーバへ中継します。

アプリケーションによっては専用のクライアントソフトウェアなどが必要です。

7-3. トンネル方式

端末に仮想ネットワークインタフェースを作成し、IPパケットなどをVPN経由で運ぶ方式です。

Webブラウザだけでなく、複数種類のアプリケーション通信を扱える構成があります。

ここで注意したいのは、TLS-VPNだからUDPアプリケーションを一切扱えないとは限らないことです。

参考書にはSSL/TLSがTCP上で動作することを前提とした説明がありますが、実際のTLS-VPN製品では、トンネル方式やUDPを利用する独自の転送方式などによって、多様な通信を扱うものがあります。

試験では、問題文に示されたVPN方式と構成を優先して判断します。

8. IPsec-VPNとTLS-VPNの比較【A：必須】

比較項目IPsec-VPNTLS-VPN
主な保護の単位IPパケット方式によってWeb通信・アプリ通信・IP通信
代表的な利用形態拠点間、リモートアクセスリモートアクセス
クライアントOS標準機能や専用ソフトなどブラウザや専用ソフトなど
代表的な技術IKE、ESPTLS、Webポータル、トンネル
セキュリティ上の重点SA、鍵、トンネル、許可通信利用者認証、公開するアプリ、端末の安全性

ここで、IPsec-VPNは拠点間専用、TLS-VPNはリモートアクセス専用と覚えてはいけません。どちらも構成や製品によって異なる用途に使えます。

9. フルトンネルとスプリットトンネル【A：必須】

リモートアクセスVPNでは、VPN接続中の端末がインターネットへアクセスするとき、どの経路を使うかが重要です。

フルトンネル

社内向け通信だけでなく、インターネット向け通信もVPN経由で会社側へ送る構成です。

会社側のプロキシやセキュリティ機器で通信を監視・制御しやすくなりますが、VPN装置や会社側ネットワークへの負荷が増えることがあります。

スプリットトンネル

社内ネットワーク宛ての通信だけをVPNへ送り、一般のインターネット向け通信は端末から直接送る構成です。

通信負荷を減らせる一方、外部向け通信が会社側のセキュリティ機器を通らない可能性があります。

したがって、スプリットトンネルを採用する場合は、端末側のセキュリティ対策やDNS・通信経路の制御なども検討する必要があります。

ただし、スプリットトンネルが存在するだけで、外部の攻撃者が社内へ直接侵入できると断定してはいけません。端末の感染、経路、アクセス制御などの条件によります。

10. VPNのセキュリティ上の限界【A：必須】

VPNが守るのは、主に指定された通信区間の機密性・完全性などです。

VPNだけでは、次の問題を解決できません。

問題VPNだけで防げるか追加対策
VPNトンネル内の盗聴適切な暗号化で対策できる強い暗号方式・鍵管理
VPN利用者の認証情報の盗難防げないMFA、認証情報の保護
VPN接続端末のマルウェア感染防げないEDR、端末管理
接続後の社内システムへの過剰なアクセス防げないACL、FW、最小権限
VPN装置自体の脆弱性悪用防げない更新、脆弱性管理
VPNトンネルの外側にある通信の盗聴VPNでは保護されないTLSなどによる別途保護

特に、VPNゲートウェイは社外から到達可能な装置となるため、脆弱性管理が重要です。

また、VPNに接続できた利用者を無条件に信頼してはいけません。接続後も、利用者・端末・アクセス先に応じて権限を制限する必要があります。

11. 設定・ログから問題を判断する【A：必須】

事例1：認証に失敗してVPNを確立できない

次のような簡略ログを考えます。

10:15:01 IKE_SA_INIT  peer=203.0.113.20
10:15:02 IKE_AUTH     peer=203.0.113.20
10:15:02 AUTH_FAILED  peer=203.0.113.20

IKEの認証処理で失敗しています。

事前共有鍵の不一致、証明書の検証失敗、認証設定の不整合などが候補になります。ただし、このログだけでは原因を一つに確定できません。

科目Bでは「認証設定や証明書の検証結果を確認する」といった具体的な調査対象を挙げます。

事例2：VPN接続後、管理用ネットワークへアクセスできる

次のログを考えます。

2026-10-18 10:20:00
user=remote_user
vpn_client_ip=10.250.0.25
dst=10.99.0.10
protocol=TCP
dst_port=22
action=ALLOW

VPN接続端末から管理用サーバ 10.99.0.10 のSSHポートへ向かう通信が許可されています。

もしその利用者に管理権限がなければ、VPNゲートウェイまたは社内のFW・ACLなどのアクセス制御を見直す必要があります。

なお、このログだけでSSHログインが成功したと断定することはできません。

事例3：スプリットトンネルで社外通信が監視されない

在宅PCのルーティング設定が次のようになっているとします。

10.0.0.0/8     -> VPNインタフェース
0.0.0.0/0      -> 自宅ルータ

この設定では、10.0.0.0/8 宛てはVPNへ、その他の一般的なIPv4通信は自宅ルータへ向かいます。より具体的な経路や例外が存在しない前提です。

会社側のセキュリティ機器で外部向け通信を監視する要件があるなら、要件と設定の整合性を確認します。

12. 科目Aの典型論点と科目Bの答案作成【A：必須】

科目Aでは、次の区別を正確に覚えます。

  • VPNは共有ネットワーク上に仮想的な通信経路を構築する。
  • トンネリング自体は暗号化を意味しない。
  • IPsecはIP層で通信を保護する。
  • ESPは暗号化に対応するが、AHは暗号化しない。
  • IPsecのトンネルモードでは、新しいIPヘッダーを付加する。
  • IKEは認証・鍵交換・SA確立に関係する。
  • NAT-TではUDP/4500が代表的に使われる。
  • VPN接続後のアクセス制御は別途必要である。

科目Bでは、単に「VPNを導入する」「暗号化する」と答えるだけでは不十分な場合があります。

例えば、VPN利用者が不要な管理用サーバにアクセスできるという問題なら、次のように記述します。

VPN接続利用者から管理用サーバへの不要な通信を遮断するため、VPNゲートウェイまたは社内FWにアクセス制御を設定し、業務上必要な宛先とポートだけを許可する。

この答案では、対象、問題のある通信、制御する場所、対策が具体的になっています。

13. 重要事項の整理と発展学習

今回の最重要ポイントは、VPNの仕組みを「仮想的な通信経路」「暗号化」「認証」「アクセス制御」に分解して理解することです。

VPNトンネルを確立しても、通信区間の外側は別途保護が必要です。また、接続相手の認証に成功しても、社内の全システムへのアクセスを許可してよいわけではありません。

C：任意の発展学習として、IKEv2の詳細なメッセージ交換、暗号スイートの細部、GRE over IPsec、L2TP/IPsec、VXLAN、Q-in-Qなどがあります。これらは今後の関連講義や復習で必要に応じて扱います。
