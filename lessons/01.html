1　到達目標と学習範囲

この講義を終えた時点で、①科目Aと科目Bで求められる能力の違い、②構成図・設定・ログから原因を導く順序、③原因・根拠・対策を区別した答案の書き方、④誤答を次の学習に生かす方法を説明できることを目標にします。試験形式の数字を覚えることより、出題された事例をどの順で読めばよいかを身に付けます。

優先度学習すること扱い
A 必須設問要求の把握、証拠の抽出、通信と認証の基本的な読み方、原因と対策の対応、簡潔な記述中心（目安75%）
B 理解補助試験制度の全体像、参考書・過去問の使い分け、学習記録の付け方補助（目安20%）
C 発展実務の高度なフォレンジック、製品固有のSIEM操作、詳細な脅威ハンティング任意（目安5%以下）

参考書で確認した範囲：巻頭「情報処理安全確保支援士試験の傾向と対策」「合格に必要なスキル・能力」「合格のための勉強法」、PDF表示・印刷ページ pp.25〜37。参考書には旧来の「午前Ⅰ・午前Ⅱ・午後」という表記が含まれます。本教材では学習上の対応を「科目A・科目B」として説明します。年度ごとの試験実施方式・受験要件の最新情報は、受験時にIPAの公式案内で別途確認してください。以下の架空のログ・答案例・図は講師独自の補足です。

2　科目Aと科目Bは何が違うのか

2.1　科目A：知識を正確に選ぶ

例えば「デジタル署名は何を検証できるか」と問われた場合、公開鍵暗号とハッシュ関数の役割を区別できれば選択肢を評価できます。ここでは定義を暗記するだけでなく、「送信者の秘密鍵で署名し、対応する公開鍵で検証する」という処理を理解しておくことが重要です。署名があるだけで内容が秘密になるわけではありません。正しい説明と、似ているが誤った説明の差を見抜く力が必要です。

2.2　科目B：与えられた条件から判断する

一方、科目Bでは、ある会社の構成図、FWの規則、Webサーバのログ、担当者の証言などが提示され、「なぜ通信が許可されたか」「どのような設定変更が必要か」と尋ねられます。FWの一般論を説明しても、その会社の設定を根拠にしなければ十分な答案にはなりません。

2.3　「知っている」と「使える」の差

「最小権限」とは、業務に必要な権限だけを付与する原則です。これを知っていても、「経理担当者のアカウントで顧客情報全件を取得できた」という設問に対し、「最小権限にする」とだけ答えるのは不十分な場合があります。なぜなら、どの主体に、どのデータへの、どの操作権限が過剰だったのかが明示されていないからです。より具体的には「経理担当者の役割から顧客情報全件の参照権限を外し、担当業務に必要な範囲に制限する」と書きます。

つまり、抽象的な原則を、問題文に登場する具体的な主体・資産・操作へ翻訳することが科目Bの基本です。

3　事例問題を解く七つの手順

  1. 設問の動詞を特定する。「原因を答えよ」「設定を示せ」「確認方法を答えよ」では求められる答えが違います。原因を聞かれているのに対策を書くと、知識が正しくても要求から外れます。
  2. 対象を特定する。どの通信、どの利用者、どのサーバ、どの時刻の話か。主語が曖昧なまま読まないことが重要です。
  3. 正常系を描く。正しい利用者がどの順番で認証し、どの機器を経由し、どの資産にアクセスするはずかを整理します。異常は正常系との比較で見つかります。
  4. 事実を抽出する。IPアドレス、時刻、規則番号、操作、成否などを拾います。推測と事実を混ぜません。
  5. 成立条件をつなぐ。「FW規則が許可」→「到達できた」、「認証に成功」→「アプリケーションを利用できた」など、証拠が直接支持する関係を組み立てます。ただし到達可能性だけで侵入成功まで断定しません。
  6. 対策を条件に対応させる。外部からの不要な通信を許可したならFW規則、認証情報の盗用なら認証強化・資格情報の失効など、原因に応じた対策を選びます。
  7. 短く答案にする。問われた要素だけを、対象と根拠が分かる形で書きます。長い一般論は不要です。
答案を作る前の3つの確認：「それは問題文に書かれているか」「その証拠でそこまで断定できるか」「その対策は今回の原因に効くか」。この3点だけで、記述の精度が上がります。

4　ケーススタディ：不審な通信をどう判断するか

架空の会社Aでは、社内の管理端末からWebサーバの管理画面へHTTPSでアクセスします。外部のインターネットからは管理画面に到達できない設計でした。ところが、深夜に外部IPアドレスから管理画面への接続記録が見つかりました。

4.1　提示された設定

FW規則（上から順に評価し、最初に一致した規則を適用）
R10  src=10.10.1.0/24    dst=203.0.113.10  tcp/443  ALLOW
R20  src=any             dst=203.0.113.10  tcp/443  ALLOW
R99  src=any             dst=any           any      DENY

R10は社内管理端末からの通信を許可する規則です。しかしR20は送信元をanyと指定しているため、宛先とポートが一致すれば社外からの通信も許可します。R99が最後に拒否していても、R20に先に一致した通信には適用されません。

4.2　提示されたログ

2026-10-10T01:14:02+09:00 FW rule=R20 action=ALLOW
 src=198.51.100.25:51842 dst=203.0.113.10:443 proto=TCP
2026-10-10T01:14:03+09:00 WEB client=198.51.100.25
 method=GET path=/admin status=200 user="-"
2026-10-10T01:14:08+09:00 AUTH client=198.51.100.25
 account=admin result=FAIL reason=bad_password

ここで確認できる事実は3つあります。①外部IPアドレスからのTCP/443通信がR20によって許可された、②Webサーバが/adminへのGET要求にHTTP 200を返した、③その後の認証試行は失敗した、ということです。

一方、この3行だけでは管理者アカウントへの不正ログイン成功は確認できません。HTTP 200はページの応答が成功したことを示すだけであり、認証の成功を意味しません。実際、認証ログはFAILです。この区別は科目Bで重要です。

4.3　設問が変わると答案も変わる

設問必要な根拠答案の方向
なぜ外部から管理画面に到達できたかR20の送信元any、宛先・ポート、ALLOWログR20が外部送信元も許可していたため
管理者ログインは成功したかAUTH result=FAILこのログでは成功を確認できない
再発を防ぐFW設定は何か本来は社内管理端末だけを許可R20の削除・制限、社外からの到達禁止
追加で確認すべきことは何かこの抜粋は一部の時間だけ前後の認証成功・操作ログを確認

注意したいのは、対策の粒度です。「セキュリティを強化する」は今回の問題の答えになりません。「送信元を社内管理用ネットワークに限定し、外部送信元の管理画面宛てTCP/443を拒否する」と具体化します。ただし、社内からのアクセスにも認証は必要です。FW制御だけでアカウント盗用を防げるわけではありません。

5　ログと設定を読むときの落とし穴

5.1　FWが許可したことと、アプリケーション処理の成功は別

FWのALLOWは通信を通過させる判断を示しますが、サーバがその通信を受け取ったか、認証に成功したか、データを返したかまでは直接示しません。通信経路の各装置は別々の事実を記録するため、FWログ・Webアクセスログ・認証ログを対応付ける必要があります。

5.2　時刻と識別子を合わせる

複数機器の時刻がずれていれば、見かけ上の順序が入れ替わります。ログのタイムゾーン、時刻同期、記録精度を確認します。また、NATやプロキシがある場合、Webサーバが見た送信元IPアドレスと元の端末のIPアドレスが一致しないことがあります。必要に応じてNAT変換ログやプロキシログを突き合わせます。

5.3　証拠の強さを段階的に考える

証拠言えることまだ言えないこと
FW ALLOWFWが当該通信を許可したログイン成功、情報流出
HTTP 200その要求に対して正常なHTTP応答が返った認証済みか、機密データ取得か
AUTH SUCCESSその認証処理が成功した本人が操作したか、データ流出したか
大量のダウンロード記録データ取得処理があった可能性内容・持出し先・悪意の有無

答案では「可能性がある」と「確認できた」を使い分けます。証拠が不足しているときは、断定せず追加確認を示す方が正確です。

6　科目Bの答案を組み立てる

6.1　原因を問う設問

弱い答案：「ファイアウォールの設定が不適切だったから。」

改善した答案：「送信元をanyとする規則R20が管理画面宛てTCP/443を許可しており、外部IPアドレスからの通信にも適用されたため。」

後者は、①具体的な設定、②影響を受ける通信、③到達可能になった因果関係が明示されています。設問の字数制限が短ければ「R20が送信元anyの管理画面宛て通信を許可していたため」と圧縮できます。

6.2　対策を問う設問

弱い答案：「アクセス制御を強化する。」

改善した答案：「管理画面宛てTCP/443の許可元を社内管理ネットワークに限定し、外部送信元を許可するR20を削除する。」

対策は、原因を成立させた条件を取り除く形で書きます。設問が「FWの設定変更」を尋ねているなら、MFAの導入だけを答えるのは要求とずれます。逆に「管理者アカウントの不正利用防止」を尋ねられたら、MFAや権限管理など別の対策が中心になります。

6.3　「確認方法」を問う設問

改善した答案：「当該送信元IPアドレスの前後の認証ログと管理画面の操作ログを突き合わせ、認証成功と管理操作の有無を確認する。」

「ログを見る」だけでは、どのログの何を確認するのかが不足します。対象と判定基準まで示すと、答案の再現性が上がります。

6.4　採点されやすい書き方の考え方

公開問題の採点基準は設問ごとに異なるため、ここで示すのは講師による一般的な答案設計です。大切なのは「誰が／何に／何をした」「どの設定・条件によって」「何が可能になった」を短文で伝えること。長い前置きや抽象的な標語を避け、問題文の用語を正確に使います。

7　217講をどう学ぶか

7.1　講義を読むとき

最初は「何が起きる仕組みか」を図で追い、次に「どこを変えると攻撃・障害が起きるか」を考えます。最後に、対策がその原因にどう作用するかを説明できるか確認します。用語の意味だけで止めず、入力→処理→出力→失敗時の挙動まで言える状態を目指します。

7.2　理解度チェックと復習

受講時には選択式6問と記述式3問（合計15点）をチャット上で出題し、回答後に採点します。ただし、この保存用HTMLには問題と採点結果を含めません。誤答は「知らなかった用語」「通信の順序を誤解」「根拠を読み落とした」「答案の対象が曖昧」のように原因別に分類し、次回の復習対象にします。

点数が高くても、根拠を説明できなかった論点は復習対象になります。反対に、初回で間違えても、なぜ間違えたかを説明できれば学習は前進しています。進捗管理では修了済みの履歴を維持し、復習によって過去の得点を書き換えません。

7.3　科目Aと科目Bの往復

科目Aの知識を学んだら、短いログや構成図に当てはめます。科目Bで詰まったら、何の基礎知識が欠けていたかを戻って確認します。例えばFW規則の読み方に困った場合、IPアドレス、サブネット、TCPポート、規則の評価順序に戻る、といった往復が効果的です。

7.4　時間の使い方

新しい講義を読む時間に加え、直近の弱点を短く復習する時間を確保します。試験直前だけにまとめて復習するのではなく、講義の直後、数日後、しばらく経った後に「自分の言葉で説明する」機会を設けます。正解選択肢を見て分かった気になるのを避け、根拠を言語化します。

8　重要事項の整理と資料の位置付け

本講の最重要事項：①科目Aの知識を科目Bの証拠読解に使う、②設問が求める対象と動詞を先に確かめる、③正常系から異常を見つける、④事実と推測を分ける、⑤原因を取り除く対策を具体的に書く、⑥ログの一部だけで侵入成功を断定しない。

参考書との対応

『徹底攻略 情報処理安全確保支援士教科書 令和7年度版』巻頭pp.25〜37の試験傾向・学習方法を確認しました。そこから「知識だけでなく問題文の読解と演習が重要」という学習方針を採用しています。本講のFW構成図、架空の通信記録、ログの解釈、答案例、七段階の読解手順は、参考書の長文転載ではなく講師が設計した補足教材です。

発展・任意学習【C】

本格的なデジタルフォレンジックでは証拠保全手順、タイムラインの正規化、SIEM相関分析などを扱いますが、初回講義では必須にしません。まずは「証拠の範囲内で結論を述べる」という原則を身に付けてください。
