第19講｜ルーティング

情報処理安全確保支援士（SC）合格講座｜第1〜23講・詳細再執筆

第18講では、IPアドレスとポート番号によって通信先を識別する仕組みを学びました。

今回のテーマは、IPパケットを目的のネットワークまで、どの経路で届けるかを決めるルーティングです。

例えば、社内PCからインターネット上のWebサーバへ通信するとき、PCは最終的なWebサーバのMACアドレスを知っているわけではありません。PCはルーティングテーブルを参照し、必要に応じてデフォルトゲートウェイへパケットを渡します。

SC試験では、この仕組みを理解したうえで、ルーティングテーブル、デフォルトルート、経路の優先順位、経路の改ざん、通信障害の切り分けを説明できることが重要です。

1. 到達目標・参考書・学習優先度

1-1. 到達目標

今回の講義では、次のことを理解します。

  1. ルーティングとルーティングテーブルの役割を説明できる。
  2. 直接接続されたネットワークと、ルータ経由のネットワークを区別できる。
  3. デフォルトゲートウェイとデフォルトルートの違いを理解する。
  4. 最長プレフィックス一致によって転送先を選択できる。
  5. スタティックルーティングとダイナミックルーティングの違いを説明できる。
  6. RIP、OSPF、BGPの基本的な役割を理解する。
  7. 経路の誤設定、経路広告の偽装、経路ハイジャックの脅威を説明できる。
  8. ルーティングテーブルと通信ログを読み、原因・影響・対策を科目B形式で記述できる。

2. ルーティングとは何か

2-1. 同じネットワーク内と、異なるネットワーク間の通信

次のネットワークを考えます。

PC-A                    ルータ                     サーバB
192.168.1.10/24     192.168.1.1               192.168.2.20/24
      |              192.168.2.1                      |
      +-------------------+---------------------------+
       192.168.1.0/24          192.168.2.0/24

PC-Aの所属ネットワークは 192.168.1.0/24、サーバBは 192.168.2.0/24 です。

PC-Aは、宛先 192.168.2.20 が自分と異なるネットワークに属すると判断します。

そこで、直接サーバBへEthernetフレームを届けようとするのではなく、ルータへ渡すことになります。

ルータは、受け取ったIPパケットの宛先IPアドレスを調べ、適切な転送先を決めます。

この処理がルーティングです。

2-2. ルーティングはIPアドレスに基づく

第10講ではMACアドレス、第11講ではARPを学びました。

それらとルーティングの役割を区別しましょう。

情報 役割
宛先IPアドレス 最終的な通信先を示す
ルーティングテーブル 宛先IPアドレスに応じた転送先を選択する
次ホップIPアドレス 次に渡すルータなどを示す
宛先MACアドレス そのリンク上で次にフレームを渡す相手を示す

つまり、IPアドレスで経路を決め、Ethernet上では次の相手のMACアドレスを使ってフレームを届けるという関係です。

2-3. ルータは最終目的地までの全経路を知っている必要があるか

必ずしもありません。

ルータは通常、自分のルーティングテーブルから、次にどこへ転送するかを判断します。

例えば、

PC → ルータA → ルータB → ルータC → サーバ

という経路では、ルータAが全ルータの詳細な転送手順を保持している必要はありません。

ルータAは次ホップのルータBへ渡し、ルータBがさらに次の転送先を判断します。

これを繰り返すことで、パケットが目的地へ到達します。

3. ルーティングテーブルの読み方

A：必須

3-1. ルーティングテーブルとは

ルーティングテーブル（経路制御表）は、宛先ネットワークに対して、どこへパケットを送るかを記録した表です。

例えば、次のようなルーティングテーブルがあるとします。

宛先ネットワーク       次ホップ          出力IF
192.168.1.0/24         直接接続          eth0
192.168.2.0/24         192.168.1.254     eth0
10.0.0.0/8             192.168.1.253     eth0
0.0.0.0/0              192.168.1.1       eth0

3-2. 各項目の意味

宛先ネットワークは、経路の適用対象となるIPアドレスの範囲です。

次ホップは、その宛先へ向かうために次に渡すルータなどを示します。

出力インターフェースは、パケットを送り出すネットワークインターフェースです。

例えば、宛先が 192.168.2.20 の場合、192.168.2.0/24 に一致する経路を利用し、次ホップ 192.168.1.254 へ送ります。

3-3. 直接接続されたネットワーク

192.168.1.0/24 → 直接接続 → eth0

これは、eth0 が 192.168.1.0/24 に直接接続されていることを示す経路の例です。

宛先が同一リンク上にあると判断される場合、通常、別のルータを経由する必要はありません。

Ethernet上では、必要に応じてARPで宛先のMACアドレスを調べて送信します。

3-4. 間接的な経路

192.168.2.0/24 → 192.168.1.254 → eth0

この経路では、宛先 192.168.2.0/24 へ向かうため、まず 192.168.1.254 に送ります。

ここで注意するのは、IPパケットの宛先IPアドレスを次ホップのIPアドレスへ書き換えるわけではないことです。

通常、転送するIPパケットの最終宛先は 192.168.2.20 のままです。

一方、次ホップへ送るEthernetフレームの宛先MACアドレスは、次ホップのMACアドレスになります。

3-5. ルーティングテーブルに一致する経路がない場合

どの経路にも一致せず、デフォルトルートも存在しない場合、通常、そのパケットを転送できません。

ルータはパケットを破棄し、状況によってはICMP Destination Unreachableを返すことがあります。

ただし、ICMPエラーの生成・送信は、設定や制限によって抑止される場合があります。

4. デフォルトゲートウェイとデフォルトルート

4-1. なぜデフォルトルートが必要なのか

世界中のネットワークについて、すべてのPCが個別の経路を保持するのは現実的ではありません。

そこで、より具体的な経路が存在しない場合に利用する経路として、デフォルトルートを設定します。

IPv4では、

0.0.0.0/0

と表します。

/0 は、宛先IPアドレスの先頭0ビットを比較する、つまりIPv4のすべての宛先に一致することを意味します。

4-2. PCのデフォルトゲートウェイ

例えば、PCの設定が次のようになっているとします。

IPアドレス       192.168.1.10
サブネットマスク 255.255.255.0
デフォルトGW     192.168.1.1

PCが 8.8.8.8 に通信する場合、宛先は直接接続された 192.168.1.0/24 に含まれません。

ほかに具体的な経路がなければ、デフォルトゲートウェイ 192.168.1.1 へパケットを送ります。

4-3. デフォルトルートとデフォルトゲートウェイの違い

用語 意味
デフォルトルート より具体的な経路がない宛先に適用する経路
デフォルトゲートウェイ PCなどがデフォルト経路で利用するルータ

デフォルトルートは経路情報、デフォルトゲートウェイは通常その転送先となるルータです。

4-4. デフォルトゲートウェイが間違っている場合

PCのIPアドレスが 192.168.1.10/24 なのに、デフォルトゲートウェイとして到達できないルータが設定されているとします。

この場合、同じネットワーク内の端末とは通信できても、別ネットワークとの通信に失敗する可能性があります。

ここで重要なのは、「LAN内の通信はできるが、外部への通信はできない」という症状が、デフォルトゲートウェイの設定不備を疑う手掛かりになることです。

ただし、同様の症状はDNS、FW、NAT、上流回線の障害などでも発生します。原因を決め付けず、順に切り分けます。

5. 最長プレフィックス一致

A：必須・経路表の計算問題

5-1. 複数の経路に一致したらどうするか

ルーティングテーブルには、宛先IPアドレスが複数の経路に一致する場合があります。

例えば、次の経路があるとします。

10.0.0.0/8         → ルータA
10.10.0.0/16       → ルータB
10.10.20.0/24      → ルータC
0.0.0.0/0          → ルータD

宛先が 10.10.20.50 の場合、四つすべてに一致します。

どの経路が選ばれるでしょうか。

答えは、最も長いプレフィックス長を持つ 10.10.20.0/24 です。

これを最長プレフィックス一致（Longest Prefix Match）といいます。

5-2. なぜプレフィックス長が長い経路を選ぶのか

プレフィックス長が長いほど、対象となるIPアドレスの範囲が狭く、より具体的な宛先を指定しています。

例えば、

経路 対象範囲の考え方
10.0.0.0/8 10で始まる広い範囲
10.10.0.0/16 10.10で始まる範囲
10.10.20.0/24 10.10.20で始まる範囲
0.0.0.0/0 すべてのIPv4宛先

10.10.20.50 に対して最も具体的な経路は /24 です。

5-3. 具体例を解く

次の経路表を考えます。

宛先ネットワーク 次ホップ
172.16.0.0/12 A
172.16.10.0/24 B
172.16.10.128/25 C
0.0.0.0/0 D

宛先IPアドレスごとの転送先を判断します。

経路選択の練習（解答と理由）

宛先IPアドレス 次ホップ 理由
172.16.10.50 B /24に一致し、/25には一致しない
172.16.10.200 C /25に一致し、最も具体的
172.20.1.10 A 172.16.0.0/12に一致
192.0.2.10 D デフォルトルートを使用

5-4. メトリックとの関係

最長プレフィックス一致は、宛先に対してどの範囲の経路を優先するかを決める原則です。

同じ宛先プレフィックスへの複数の経路が存在する場合には、経路の情報源の優先度やメトリックなどが選択に影響します。

したがって、プレフィックス長とメトリックを同じ基準として比較してはいけません。

例えば、10.10.20.0/24 のメトリックが大きく、10.0.0.0/8 のメトリックが小さいからといって、10.10.20.50 宛ての転送で必ず /8 が選ばれるわけではありません。

通常は、利用可能な経路のうち、より具体的な /24 が優先されます。

6. 実際のパケット転送の流れ

6-1. ネットワーク構成

次の構成を考えます。

PC-A                   ルータA                 ルータB                 サーバB

192.168.1.10       192.168.1.1             10.0.0.2             192.168.2.20
       |                 |                      |                      |
       +-----------------+                      |                      |
                    10.0.0.1 -------------------+                      |
                                               192.168.2.1 ------------+

PC-AからサーバBへTCP通信を行います。

6-2. PC-Aの判断

PC-Aの設定は次のとおりです。

IPアドレス：192.168.1.10/24
デフォルトGW：192.168.1.1
宛先IP：192.168.2.20

PC-Aは、宛先が自分の直接接続ネットワーク外であると判断します。

そこで、次ホップである 192.168.1.1 にパケットを渡します。

このとき、Ethernetを利用していれば、ARPでルータAのMACアドレスを取得することがあります。

6-3. IPヘッダとEthernetヘッダの違い

PC-AからルータAへ送るフレームは、概念的に次のようになります。

Ethernetヘッダ
  送信元MAC：PC-A
  宛先MAC　：ルータA

IPヘッダ
  送信元IP：192.168.1.10
  宛先IP　：192.168.2.20

ここが重要です。

Ethernetの宛先MACアドレスは次ホップのルータAですが、IPの宛先アドレスは最終目的地のサーバBです。

6-4. ルータAでの処理

ルータAはフレームを受信すると、IPパケットを取り出します。

そして、宛先IPアドレス 192.168.2.20 を使ってルーティングテーブルを検索します。

例えば、

192.168.2.0/24 → 次ホップ 10.0.0.2

という経路があれば、ルータBへ転送します。

その際、次のリンクに応じて新しいリンク層フレームを作成します。

Ethernet区間であれば、通常、送信元MACアドレスと宛先MACアドレスが変わります。

6-5. ルータを通過するたびに変わるもの

情報 通常のIPv4ルータ転送
宛先IPアドレス 変わらない
送信元IPアドレス 変わらない
TTL 1減る
IPv4ヘッダチェックサム TTL変更に伴って更新される
送信元MACアドレス 次のEthernetリンクに応じて変わる
宛先MACアドレス 次ホップに応じて変わる

ただし、NAT/NAPTを行う機器では、IPアドレスやポート番号が変換されることがあります。

また、トンネリングなど特殊な構成では、パケットの扱いが異なる場合があります。

6-6. 返信は同じ経路を戻るのか

必ずしもそうではありません。

IPネットワークでは、往路と復路が異なる経路になることがあります。これを非対称ルーティングといいます。

例えば、

往路：PC → ルータA → ルータB → サーバ
復路：サーバ → ルータC → ルータA → PC

という経路もあり得ます。

非対称ルーティング自体は必ずしも異常ではありませんが、ステートフルファイアウォールなどの状態管理に影響する場合があります。

7. TTLとルーティングループ

7-1. ルーティングループとは

ルータ間で経路設定が不適切な場合、パケットが同じルータを繰り返し通過することがあります。

例えば、

ルータA：宛先XはルータBへ
ルータB：宛先XはルータAへ

という状態です。

         宛先Xへのパケット
                 |
                 v
              ルータA
                 |
                 v
              ルータB
                 |
                 +--------→ ルータA
                                |
                                v
                             ルータB
                                :

このような状態をルーティングループと呼びます。

7-2. TTLの役割

IPv4にはTTL（Time To Live）というフィールドがあります。

ルータがパケットを転送するとき、通常TTLを1減らします。

例えば、

送信時 TTL = 4

ルータA通過後 TTL = 3
ルータB通過後 TTL = 2
ルータA通過後 TTL = 1
次の転送時にTTLが尽きる

TTLが尽きたパケットは転送されず、破棄されます。

これにより、ルーティングループが発生しても、パケットが無制限に転送され続けることを防ぎます。

7-3. ICMP Time Exceeded

TTLが尽きた場合、ルータはICMP Time Exceededを送信元へ返すことがあります。

IPv4では、代表的に次のメッセージです。

ICMP Type = 11
Code = 0

第15講で学んだICMPの知識とつながります。

7-4. TTLは時間を秒単位で計測しているのか

名前はTime To Liveですが、実際のIP転送では、ルータを通過する際に減らされるホップ数制限として理解するとよいでしょう。

IPv6では同様の役割を持つフィールドがHop Limitと呼ばれます。

8. tracerouteによる経路確認

B：理解補助／障害切り分けはA

8-1. tracerouteとは

traceroute やWindowsの tracert は、宛先までの経路上にあるルータなどを調査するためのツールです。

基本的には、TTLやHop Limitを変えたパケットを送信し、途中のルータから返されるICMP Time Exceededなどを利用します。

8-2. 具体的な動作

例えば、宛先まで3台のルータを通る場合を考えます。

PC → ルータA → ルータB → ルータC → サーバ

TTLを1にすると、ルータAでTTLが尽きます。

TTLを2にすると、ルータBで尽きます。

TTLを3にすると、ルータCで尽きます。

このようにTTLを増やしていくことで、経路上のルータを推定します。

8-3. 出力例

traceroute to 203.0.113.10

1  192.168.1.1
2  10.0.0.2
3  198.51.100.1
4  203.0.113.10

これは説明用の例です。

各行は、途中で観測されたルータなどを示します。

8-4. 途中で応答がなくなる場合

1  192.168.1.1
2  10.0.0.2
3  * * *
4  203.0.113.10

3ホップ目で応答がなくても、必ずしもそのルータで通信が停止したわけではありません。

例えば、ルータがICMP Time Exceededを返さない、または応答を制限している可能性があります。

実際、この例では4ホップ目の宛先まで到達しています。

したがって、tracerouteで途中のホップが表示されないことと、その地点で転送が失敗したことは同義ではありません。

8-5. tracerouteとpingの違い

ツール 主な用途
ping 宛先への到達性や応答時間などを確認する
traceroute / tracert 宛先までの途中経路を推定する

両方とも、ICMPやその他のプローブ通信が制限されている環境では、結果の解釈に注意が必要です。

9. スタティックルーティングとダイナミックルーティング

9-1. スタティックルーティング

スタティックルーティングは、管理者が経路を手動で設定する方式です。

例えば、

宛先：192.168.2.0/24
次ホップ：10.0.0.2

という経路を登録します。

メリットは、構成が比較的単純で、意図しない経路変更を抑えやすいことです。

一方、ネットワークの変更や障害が発生した場合、経路を手動で変更する必要が生じることがあります。

9-2. ダイナミックルーティング

ダイナミックルーティングは、ルータ同士が経路情報を交換し、ルーティングプロトコルによって経路を学習・更新する方式です。

例えば、

ルータA ←経路情報→ ルータB
   ↑                    ↑
経路表を更新         経路表を更新

という処理を行います。

経路障害が発生した場合、プロトコルの動作によって代替経路へ切り替えられることがあります。

ただし、切替えが必ず瞬時に完了するわけではありません。

9-3. 両者の比較

項目 スタティック ダイナミック
経路登録 管理者が設定 ルーティングプロトコルで学習
構成変更 手動対応が必要な場合が多い 自動的に更新できる場合がある
管理負担 小規模では比較的少ない 設計・監視が必要
障害対応 代替経路の設定が必要 経路再計算・切替えが可能
セキュリティ上の注意 設定ミス、不正な設定変更 不正な経路広告、隣接関係の悪用

9-4. ダイナミックルーティングなら安全か

いいえ。

ルータが他の機器から経路情報を学習するということは、誤った経路情報を受け入れると通信経路が変わる可能性があるということです。

そのため、ルーティングプロトコルの認証、隣接ルータの制限、受け入れる経路のフィルタリングなどが重要になります。

10. RIP・OSPF・BGPの基本

B：仕組みの理解／A：経路広告の脅威と対策

10-1. 自律システム（AS）

インターネットは、多数の組織やネットワークが相互に接続された構造です。

一定の経路制御方針の下で管理されるネットワーク群を、自律システム（AS：Autonomous System）と呼びます。

経路制御のプロトコルは、AS内部で使用するものと、AS間で使用するものに大きく分けられます。

10-2. RIP

RIP（Routing Information Protocol）は、代表的なディスタンスベクタ型ルーティングプロトコルです。

主にホップ数を経路選択の指標として利用します。

ホップ数とは、経路上で通過するルータの数を表す考え方です。

例えば、

経路A：ルータ2台を経由
経路B：ルータ4台を経由

なら、RIPでは通常、ホップ数の小さい経路が優先されます。

ただし、ホップ数が少ない経路が必ず高速とは限りません。

また、RIPには経路規模や収束に関する制約があります。

10-3. OSPF

OSPF（Open Shortest Path First）は、代表的なリンクステート型ルーティングプロトコルです。

ルータ間でリンク状態に関する情報を交換し、ネットワークの構成を基に経路を計算します。

経路選択ではコストを使用します。

例えば、ネットワーク内で複数の経路がある場合、設定されたコストに基づいて適切な経路を選択します。

OSPFでは、正当なルータ間で経路情報を交換するため、隣接関係の管理や認証などがセキュリティ上重要です。

10-4. BGP

BGP（Border Gateway Protocol）は、主にAS間の経路情報交換に使われるプロトコルです。

インターネット全体の経路制御において重要な役割を担っています。

BGPでは、単純にホップ数だけで経路を決めるのではなく、経路属性や運用ポリシーなどを利用します。

例えば、あるASが別のASに対して、

203.0.113.0/24 へは自AS経由で到達できる

という経路情報を広告することがあります。

10-5. 三つのプロトコルの比較

プロトコル 主な利用範囲 経路制御の考え方
RIP AS内部 ディスタンスベクタ、ホップ数
OSPF AS内部 リンクステート、コスト
BGP 主にAS間 パスベクタ、経路属性・ポリシー

SC試験対策としては、まずどの範囲で使用され、どのような経路情報を扱うかを理解してください。

OSPFの詳細なLSA形式やBGPの多数の属性を暗記することは、今回の優先事項ではありません。

11. ルーティングに関係するセキュリティ上の脅威

A：必須

11-1. 経路の誤設定

最も基本的な問題は、ルーティングテーブルの誤設定です。

例えば、

本来：
192.168.2.0/24 → ルータB

誤設定：
192.168.2.0/24 → ルータC

となっている場合、ルータCが適切な経路を持っていなければ、通信が失敗する可能性があります。

さらに、ルータCが意図しないネットワークへ転送すれば、通信経路が変わる可能性があります。

11-2. 不正な経路広告

ダイナミックルーティングでは、ルータが他のルータから経路情報を学習します。

攻撃者が不正な経路情報を受け入れさせると、通信を攻撃者側へ誘導できる可能性があります。

例えば、

本来の経路：
PC → 正規ルータ → サーバ

不正経路：
PC → 攻撃者側ルータ → サーバ

という経路に変更されると、通信の盗聴や改ざんを試みられる可能性があります。

ただし、経路を誘導できたからといって、TLSなどで適切に保護された通信の内容を直ちに復号できるわけではありません。

11-3. BGPハイジャック

BGPハイジャックは、不正または誤ったBGP経路広告によって、本来とは異なるASへ通信が誘導されるなどの問題です。

例えば、本来のASが広告しているプレフィックスについて、別のASが誤った到達性を広告すると、ネットワークによってはその経路を選択する可能性があります。

影響としては、次のようなものが考えられます。

  • 通信が到達しなくなる。
  • 通信が意図しない経路へ流れる。
  • 通信が第三者のネットワークを経由する。
  • サービスの可用性が低下する。

11-4. より具体的な経路の悪用

第5節で学んだ最長プレフィックス一致を思い出してください。

例えば、本来の経路が、

203.0.112.0/23 → 正規AS

であるとします。

これに対して、別の経路として、

203.0.113.0/24 → 不正なAS

が受け入れられた場合、203.0.113.0/24 宛ての通信では、より具体的な /24 が選択される可能性があります。

これは、最長プレフィックス一致の性質が、経路ハイジャックの影響を考えるうえでも重要であることを示します。

ただし、実際のインターネットで経路が採用されるかどうかは、経路フィルタリングやBGPポリシーなどにも左右されます。

11-5. 経路ループ・ブラックホール

不適切な経路によって、パケットがルータ間を循環することがあります。

また、経路上でパケットが破棄され、宛先へ届かなくなることもあります。

後者のような通信の吸い込み・破棄を、文脈によってブラックホールと呼ぶことがあります。

なお、DDoS対策では、意図的に攻撃トラフィックを破棄するブラックホールルーティングが使われる場合もあります。

そのため、ブラックホールという言葉は、常に攻撃を意味するわけではありません。

12. ルーティングに対する防御策

12-1. 経路広告の認証

OSPFなどでは、ルーティングプロトコルがサポートする認証機能を利用し、正当なルータとの経路情報交換を保護することが重要です。

ただし、認証だけですべての経路の正当性を保証できるわけではありません。

認証済みのルータが誤設定された場合などには、誤った経路情報が広がる可能性があります。

12-2. 経路フィルタリング

ルータが受信・広告する経路情報を制限します。

例えば、外部の接続先から受け取る必要のない内部ネットワークの経路情報を拒否する設定が考えられます。

また、BGPでは、接続先ごとに許可するプレフィックスを制限することが重要です。

12-3. RPKIとROV

BGPの経路広告に関係する対策として、RPKI（Resource Public Key Infrastructure）があります。

RPKIでは、IPアドレス資源の保有者が、どのASにプレフィックスの広告を許可するかを示すROAを公開できます。

ROV（Route Origin Validation）は、この情報を利用して、BGP経路の起点ASなどを検証する仕組みです。

ただし、RPKI/ROVはBGP経路のすべての経路属性や転送経路全体を保証するものではありません。

試験対策では、BGPの不正な経路広告に対する対策の一つとして、起点ASの検証があると理解してください。

12-4. 経路変更の監視

正常時の経路と比較して、突然の経路変更が発生していないか監視します。

例えば、次のような変化があれば、調査対象になります。

変更前：
10.10.0.0/16 → 192.168.1.254

変更後：
10.10.0.0/16 → 192.168.1.200

管理者が意図していない次ホップへの変更であれば、設定ミスや不正な経路広告などが疑われます。

12-5. 冗長化とVRRP

参考書p.170では、デフォルトゲートウェイの冗長化技術としてVRRPが説明されています。

VRRP（Virtual Router Redundancy Protocol）は、複数のルータで仮想ルータを構成し、端末が利用するデフォルトゲートウェイを冗長化する仕組みです。

例えば、

PC
デフォルトGW：192.168.1.1（仮想IP）
          |
          v
       VRRP構成
       /      \
   ルータA   ルータB

という構成にします。

ルータAが障害になった場合、構成と条件に応じてルータBが仮想ルータの役割を引き継ぐことができます。

ただし、VRRPを導入しただけで上流ネットワークやインターネット接続のすべての障害に対応できるわけではありません。

13. 通信障害の切り分け

A：必須・科目B重点

13-1. LAN内は通信できるが、外部に接続できない

次の状況を考えます。

PC：192.168.1.10/24
GW：192.168.1.254

同じLANのサーバ：通信可能
外部Webサーバ：通信不可

この場合、次の順番で調査します。

  1. PCのIPアドレス・サブネットマスクは正しいか。
  2. デフォルトゲートウェイのIPアドレスは正しいか。
  3. ゲートウェイへ到達できるか。
  4. ゲートウェイ以降のルーティングテーブルは正しいか。
  5. FW、NAT、DNSなどに問題はないか。

13-2. 特定ネットワークだけ到達できない

例えば、

192.168.2.0/24 → 通信可能
192.168.3.0/24 → 通信不可
インターネット → 通信可能

という場合です。

すべての通信が失敗しているわけではないので、特定宛先の経路に問題がある可能性があります。

ルーティングテーブルで 192.168.3.0/24 に一致する経路を確認します。

また、復路の経路が正しいかも確認します。

13-3. 往路は届くが応答が返らない

例えば、PCからサーバへTCP SYNが届いていることをサーバ側で確認できたとします。

しかし、PCにはSYN+ACKが届きません。

この場合、サーバからPCへの戻り経路に問題がある可能性があります。

もちろん、サーバがSYN+ACKを送信していない、またはFWが遮断している可能性もあります。

そのため、次のように調査します。

① PCがSYNを送信したか
② サーバがSYNを受信したか
③ サーバがSYN+ACKを送信したか
④ 戻り経路のルーティングが正しいか
⑤ 途中のFWで破棄されていないか

13-4. ルーティングとDNSの切り分け

「Webサイトへアクセスできない」という症状だけでは、ルーティング障害とは限りません。

例えば、IPアドレスを直接指定すると通信できるのに、ドメイン名ではアクセスできない場合、DNSの問題が疑われます。

逆に、IPアドレスへの通信も失敗する場合には、ルーティング、FW、サーバなどを調査します。

名前解決の失敗と、IPパケットの転送失敗を区別することが重要です。

14. ルーティングテーブルとログの演習

14-1. 経路表から次ホップを判断する

次のルーティングテーブルがあります。

宛先ネットワーク      次ホップ
10.0.0.0/8            192.168.1.1
10.20.0.0/16          192.168.1.2
10.20.30.0/24         192.168.1.3
0.0.0.0/0             192.168.1.254

宛先 10.20.30.100 の場合、10.20.30.0/24 に一致する経路が最も具体的なので、次ホップは 192.168.1.3 です。

宛先 10.20.40.100 なら、10.20.0.0/16 が最も具体的なので、次ホップは 192.168.1.2 です。

宛先 192.0.2.10 なら、提示された経路の中ではデフォルトルートが選ばれます。

14-2. 経路変更ログ

次のログを考えます。

10:00:00
Route added:
10.20.0.0/16 via 192.168.1.2

10:15:00
Route removed:
10.20.0.0/16 via 192.168.1.2

10:15:01
Route added:
10.20.0.0/16 via 192.168.1.200

15分後に、同じ宛先プレフィックスの次ホップが変更されています。

このログからは、経路が変化したことは分かります。

しかし、これだけで攻撃と断定できません。

障害による経路切替え、管理者による設定変更、不正な経路広告など、複数の可能性があります。

調査では、変更元、設定履歴、ルーティングプロトコルのログ、変更前後の到達性などを確認します。

14-3. デフォルトルートの欠落

宛先ネットワーク      次ホップ
192.168.1.0/24        直接接続
192.168.2.0/24        192.168.1.254

この経路表には、デフォルトルートがありません。

宛先 8.8.8.8 への通信では、提示された経路に一致するものがありません。

したがって、別の経路情報がなければ、パケットを送信できません。

科目Bでは、「インターネットに接続できない」という結果だけでなく、宛先に一致する経路が存在しないことを原因として記述します。

14-4. より具体的な不正経路

正規経路：
203.0.112.0/23 via 198.51.100.1

追加された経路：
203.0.113.0/24 via 198.51.100.200

宛先が 203.0.113.50 の場合、両方の経路に一致します。

しかし、/24 の方が具体的なので、通常は追加された経路が選ばれます。

この経路が不正に追加されたものであれば、通信が意図しない次ホップへ誘導される可能性があります。

ここでは、最長プレフィックス一致がセキュリティ上の判断にも関係していることを確認してください。

16. 科目Bの答案作成ポイント

16-1. 設問例①：デフォルトゲートウェイ

設問

PCが同一ネットワーク内のサーバとは通信できるが、別ネットワークへ通信できない。デフォルトゲートウェイの設定が原因となる理由を説明せよ。

答案例

「別ネットワーク宛てのパケットを転送する次ホップが誤って設定されているため、PCが正しいルータへパケットを送信できないから。」

解説

「ゲートウェイが間違っているから」だけではなく、誤設定が転送に与える影響まで説明します。

16-2. 設問例②：最長プレフィックス一致

設問

10.0.0.0/8 と 10.10.20.0/24 の経路が存在する。宛先 10.10.20.50 に対して /24 の経路が選択される理由を説明せよ。

答案例

「両方の経路に一致するが、10.10.20.0/24 の方がプレフィックス長が長く、より具体的な宛先を示すため。」

16-3. 設問例③：往路と復路

設問

クライアントから送信したTCP SYNはサーバへ到達しているが、SYN+ACKがクライアントへ届かない。ルーティングの観点から確認すべきことを説明せよ。

答案例

「サーバからクライアントへの戻り経路が正しく設定されているかを確認し、SYN+ACKが適切な次ホップへ転送されているか調査する。」

16-4. 設問例④：経路ハイジャック

設問

攻撃者が正規の経路より具体的な宛先プレフィックスを不正に広告した場合、通信が攻撃者側へ誘導される可能性がある理由を説明せよ。

答案例

「ルータが宛先に一致する経路のうち最長プレフィックスを優先するため、不正に広告されたより具体的な経路が選択される可能性があるから。」

16-5. 設問例⑤：経路広告の対策

設問

ルーティングプロトコルによって不正な経路情報が学習されることを防ぐための対策を説明せよ。

答案例

「ルーティングプロトコルの認証や隣接ルータの制限を行い、受信する経路情報をフィルタリングして不正な経路の学習を抑える。」

16-6. 設問例⑥：tracerouteの解釈

設問

tracerouteで途中のルータから応答が得られなかった。これだけで通信障害が発生していると断定できない理由を説明せよ。

答案例

「ルータがICMP Time Exceededの送信を制限または抑止していても、パケット自体は転送されている場合があるため。」

16-7. 科目Bで使う判断手順

ルーティング関連の設問では、次の順序で考えます。

  1. ① 宛先を確認 — 通信先のIPアドレスとプレフィックスを確認する。
  2. ② 経路表を確認 — 一致する経路と最長プレフィックスを判断する。
  3. ③ 次ホップを確認 — 選ばれた転送先が正しいか確認する。
  4. ④ 往路・復路を確認 — 片方向だけの通信障害ではないか調べる。
  5. ⑤ 原因を特定 — 誤設定、経路欠落、不正広告、FWなどを切り分ける。
  6. ⑥ 対策を記述 — 経路修正、経路フィルタリング、認証、監視などを対応付ける。

17. 重要事項の整理

第一に、ルーティングは宛先IPアドレスに基づいて転送先を決める処理です。 ルータはルーティングテーブルを参照し、次ホップを選択します。

第二に、最終宛先IPアドレスと次ホップIPアドレスは異なります。 Ethernetでは、次ホップへフレームを届けるため、そのリンク上のMACアドレスを使用します。

第三に、デフォルトルートは 0.0.0.0/0 です。 より具体的な経路が存在しない場合に使用されます。

第四に、最長プレフィックス一致では、宛先に一致する最も具体的な経路を優先します。 /24 と /16 の両方に一致するなら、通常は /24 が選ばれます。

第五に、IPパケットはルータを通過するたびにTTLが減少します。 TTLが尽きると破棄され、ICMP Time Exceededが返る場合があります。

第六に、スタティックルーティングは手動設定、ダイナミックルーティングはプロトコルによる経路学習です。 どちらにも管理上・セキュリティ上の注意点があります。

第七に、経路広告の偽装や誤設定は、通信の誘導や停止につながる可能性があります。 経路フィルタリング、認証、監視などで対策します。

第八に、通信障害では往路だけでなく復路の経路も確認します。 片方向にパケットが届いても、戻り経路に問題があれば通信が成立しないことがあります。

C：発展学習として切り分ける内容

今回の理解度チェックでは、次の内容を前提としません。

  • OSPFのLSAタイプやエリア設計の詳細
  • BGPのLOCAL_PREF、MED、AS_PATHなどを使った高度なポリシー設計
  • IS-ISなどのルーティングプロトコルの詳細
  • ECMPやポリシーベースルーティングの詳細設定
  • ルータ製品固有の設定コマンド
  • BGPの経路収束アルゴリズムや大規模インターネット経路運用

今回の最優先事項は、経路表から正しい次ホップを選択し、経路の誤設定や不正な経路広告による影響を説明できることです。
