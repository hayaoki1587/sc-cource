第11講｜ARP（Address Resolution Protocol）

第1〜23講 再執筆シリーズ｜第II部 ネットワーク完全攻略｜チャット版

第10講では、EthernetとMACアドレス、L2スイッチの学習・転送処理を学びました。

今回は、その知識を使って「IPアドレスしか分からない相手へ、どうやってEthernetフレームを届けるのか」を解説します。この問題を解決するのがARPです。

さらに、ARPの仕組みには、攻撃者が他人の通信を自分の端末へ誘導できるというセキュリティ上の弱点があります。第11講では、正常な通信からARP Spoofing（ARP偽装）、中間者攻撃、対策までを一続きの仕組みとして理解します。

1. 到達目標と参考書

1-1. この講義でできるようになること

  1. ARPが必要な理由を、IPアドレスとMACアドレスの役割から説明できる。
  2. ARP RequestとARP Replyの通信手順を説明できる。
  3. 同一ネットワーク宛てと別ネットワーク宛てで、ARPの問い合わせ先がどう変わるか判断できる。
  4. ARPキャッシュとスイッチのMACアドレステーブルを区別できる。
  5. ARP Spoofingによる中間者攻撃の成立過程を説明できる。
  6. ARPテーブルや通信ログから不審な対応関係を見つけ、適切な対策を記述できる。

1-2. 参考書の対応箇所

『徹底攻略 情報処理安全確保支援士教科書 令和7年度版』

  • 第3章「ネットワーク基礎技術」
  • 3-1「TCP/IP」
  • pp.171〜172：ARPの役割、同一ネットワークと異なるネットワークでのアドレス解決、IPv6との違い

参考書のこの箇所を確認しました。参考書では、ARPをIPアドレスからMACアドレスを求めるプロトコルとして説明し、通信相手が別ネットワークに存在するときには、次に送るルータのMACアドレスを調べることを示しています。

以下では、ARP Request／Replyの詳細、ARPキャッシュの具体例、ARP Spoofing、Dynamic ARP Inspectionなどは講師による技術補足として説明します。これらすべてが上記2ページに記載されているという意味ではありません。

1-3. 学習優先度

今回の中心はAです。特に、ARPで問い合わせるIPアドレスは何か、なぜ偽装されたARP情報を信じてしまうのかを重点的に理解してください。

2. そもそもARPはなぜ必要なのか

2-1. IPアドレスが分かるだけではEthernetで送れない

次のようなLANを考えます。

L2スイッチ（VLAN 10）

        ┌───────────────────────┐
        │ L2スイッチ（VLAN 10） │
        └───────────┬───────────┘
              ┌─────┴─────┐
             PC-A        PC-B
 IP：192.168.1.10     IP：192.168.1.20
 MAC：02:00:00:00:00:0A  MAC：02:00:00:00:00:0B

両端末のサブネットマスクは255.255.255.0（/24）とします。

PC-AがPC-Bへデータを送りたいとします。PC-Aのアプリケーションは、宛先IPアドレス 192.168.1.20 を使って通信しようとします。

しかし、Ethernetで実際にフレームを送るには、Ethernetヘッダに宛先MACアドレスを設定しなければなりません。

PC-Aが分かっている情報は次のとおりです。

情報 値 状態
送信元IP 192.168.1.10 分かっている
宛先IP 192.168.1.20 分かっている
送信元MAC 02:00:00:00:00:0A 分かっている
宛先MAC 不明 調べる必要がある

この不足を解決するのがARP（Address Resolution Protocol）です。

2-2. ARPが解決する問題

ARPは、IPv4アドレスに対応するMACアドレスを、同じリンク上で調べるためのプロトコルです。

知っている情報
  IPアドレス：192.168.1.20

       ↓ ARPによる問い合わせ

得られる情報
  MACアドレス：02:00:00:00:00:0B

この処理をアドレス解決（Address Resolution）と呼びます。ARPは、IPパケットを送信するために必要なリンク層の宛先情報を得る役割を持っています。

ここで注意したいのは、ARPがインターネット全体に問い合わせる仕組みではないことです。ARPの問い合わせは、原則として同じブロードキャストドメイン内で行われます。

3. ARP RequestとARP Replyの通信手順

ここは第11講で最も重要な正常系の処理です。

3-1. 最初にARPキャッシュを確認する

PC-Aが 192.168.1.20 へ送信するとき、毎回ARPを送るとは限りません。まず、PC-Aは自分が保持しているARPキャッシュを確認します。

ARPキャッシュとは、IPアドレスとMACアドレスの対応を一時的に記憶する情報です。例えば、次のような表です。

IPv4アドレス MACアドレス
192.168.1.1 02:00:00:00:00:01
192.168.1.30 02:00:00:00:00:0C

この時点では、PC-Bの 192.168.1.20 がありません。そこでPC-Aは、ARP Requestを送信します。

3-2. ARP Requestを送信する

ARP Requestは、簡単に言うと次の問い合わせです。

「192.168.1.20を使っている機器は誰ですか。あなたのMACアドレスを教えてください」

PC-Aは、この問い合わせをEthernetのブロードキャストフレームに格納します。

Ethernetヘッダ
  送信元MAC：02:00:00:00:00:0A
  宛先MAC　：FF:FF:FF:FF:FF:FF

ARPの主な内容
  操作　　　：Request
  送信元IP　：192.168.1.10
  送信元MAC：02:00:00:00:00:0A
  対象IP　　：192.168.1.20
  対象MAC　：不明

宛先MACアドレスがブロードキャストなのは、PC-AがまだPC-BのMACアドレスを知らないからです。特定のMACアドレスへ送れないため、同じブロードキャストドメイン内の機器へ問い合わせます。

3-3. L2スイッチはどう動くか

L2スイッチがARP Requestを受信すると、通常、同じVLAN内の他の転送可能なポートへブロードキャストフレームを転送します。

ここではPC-Bだけでなく、同じVLANの他のPCもARP Requestを受け取ります。ただし、問い合わせ対象のIPアドレスが自分のものでなければ、通常、その問い合わせに対してARP Replyを返しません。

3-4. PC-BがARP Replyを返す

PC-Bは、自分のIPアドレスが 192.168.1.20 であることを確認します。そして、PC-AへARP Replyを返します。

「192.168.1.20は私です。MACアドレスは02:00:00:00:00:0Bです」

通常のARP Replyは、問い合わせ元PC-A宛てのユニキャストフレームとして送信されます。

Ethernetヘッダ
  送信元MAC：02:00:00:00:00:0B
  宛先MAC　：02:00:00:00:00:0A

ARPの主な内容
  操作　　　：Reply
  送信元IP　：192.168.1.20
  送信元MAC：02:00:00:00:00:0B
  対象IP　　：192.168.1.10
  対象MAC　：02:00:00:00:00:0A

PC-Bは、ARP Requestに含まれていたPC-AのMACアドレスを利用できるため、返信先のMACアドレスを知っています。

3-5. PC-AがARPキャッシュへ登録する

PC-AがARP Replyを受信すると、得られた対応関係をARPキャッシュへ記録します。

192.168.1.20
      ↓
02:00:00:00:00:0B

これでPC-Aは、PC-B宛てのEthernetフレームを作成できます。

3-6. 一連の通信を時系列で整理する

PC-A                                  PC-B
  │ ① ARPキャッシュを確認              │
  │    対象IPが未登録                  │
  │                                    │
  ├── ② ARP Request ────────────────→│
  │       ブロードキャスト             │
  │                                    │
  │                    ③ 自分のIPと一致│
  │                                    │
  │←─────────────── ④ ARP Reply ─────┤
  │                    通常ユニキャスト│
  │                                    │
  │ ⑤ ARPキャッシュを更新              │
  │                                    │
  ├── ⑥ 本来のデータを送信 ─────────→│
  │       宛先MACはPC-B                │

同一LAN内のARP解決を単純化した図。ARP Requestは他の同一VLAN端末にも届きます。

順序は、ARPキャッシュ確認 → ARP Request → ARP Reply → キャッシュ登録 → Ethernetフレーム送信です。

試験でこの手順を説明するときは、「ARPを使う」とだけ書かず、どの端末が、どのIPアドレスについて問い合わせ、どのMACアドレスを取得するかまで書けるようにしてください。

4. 別ネットワーク宛てのARPはどうなるか

ここは科目Bの答案で間違えやすい部分です。

4-1. 宛先が別ネットワークの場合

次の構成を考えます。

機器 IPアドレス MACアドレス
PC-A 192.168.1.10/24 02:00:00:00:00:0A
ルータのLAN側 192.168.1.1/24 02:00:00:00:00:01
Webサーバ 203.0.113.80 別リンク上のMAC

PC-Aのデフォルトゲートウェイは 192.168.1.1 です。PC-AがWebサーバ 203.0.113.80 へ通信したいとします。

ここで問題です。PC-Aは、203.0.113.80のMACアドレスをARPで問い合わせるのでしょうか。

答えは、通常は問い合わせません。

4-2. なぜWebサーバのMACアドレスを調べないのか

Webサーバは、PC-Aとは別のIPネットワークに存在します。PC-Aは、そのサーバへ直接Ethernetフレームを届けることができません。

そこで、PC-Aはルーティングテーブルを参照し、パケットを次に渡す相手を決定します。この例では、次に渡す相手はデフォルトゲートウェイ 192.168.1.1 です。

そのため、PC-AがARPで調べる対象は次のIPアドレスです。

192.168.1.1

つまり、最終宛先のIPアドレスではなく、次にフレームを渡す機器のIPv4アドレスをARPで解決します。

4-3. EthernetヘッダとIPヘッダを比較する

PC-Aからルータへ送る最初のフレームは、次のようになります。

項目 設定値
Ethernet送信元MAC PC-AのMAC
Ethernet宛先MAC ルータのLAN側MAC
IP送信元アドレス 192.168.1.10
IP宛先アドレス 203.0.113.80

ここに第9講とのつながりがあります。Ethernetの宛先MACアドレスは次の配送先を示します。IPの宛先アドレスは最終的な通信相手を示します。

PC-A（192.168.1.10） → ルータ（192.168.1.1） → Webサーバ（203.0.113.80）
       最初のEthernetフレームの宛先MAC＝ルータ
       IPパケットの宛先IP＝Webサーバ（最終宛先）

ルータが別のEthernetリンクへ転送するときには、通常、そのリンクに合わせてEthernetヘッダを作り直します。一方、IP宛先アドレスは、NATなどによる書換えがなければWebサーバのままです。

4-4. 試験での正確な説明

例えば「PC-Aが外部Webサーバへ通信する際、ARPで解決するIPアドレスを答えよ」と問われたら、答えるべきなのはWebサーバのIPアドレスではありません。

問題文に示されたデフォルトゲートウェイの具体的なIPアドレスです。単に「ルータのIPアドレス」と書くより、設問に与えられた 192.168.1.1 を用いる方が、答案として明確です。

5. ARPキャッシュとMACアドレステーブルの違い

第10講との関連で必ず区別してほしい二つの表があります。

5-1. ARPキャッシュ

ARPキャッシュは、主にホストやルータが使用します。管理する対応関係は、次のとおりです。

IPv4アドレス → MACアドレス

例：

192.168.1.20 → 02:00:00:00:00:0B

これは「このIPv4アドレスへフレームを送るには、どのMACアドレスを使うか」という情報です。

5-2. MACアドレステーブル

L2スイッチが使用するMACアドレステーブルは、別の情報を管理します。

MACアドレス ＋ VLAN → スイッチのポート

例：

02:00:00:00:00:0B ＋ VLAN 10 → ポート2

これは「このMACアドレス宛てのフレームを、どのポートへ転送するか」という情報です。

5-3. 二つの仕組みが連携する

PC-AがPC-Bへデータを送る場合、次のように処理が進みます。

PC-A：ARPキャッシュを参照
  192.168.1.20 → 02:00:00:00:00:0B
  宛先MACアドレスを決定
          ↓
PC-A：Ethernetフレームを送信
  宛先MAC：02:00:00:00:00:0B
          ↓
L2スイッチ：MACアドレステーブルを参照
  02:00:00:00:00:0B → ポート2
  ポート2へ転送
          ↓
PC-Bがフレームを受信

ARPキャッシュが正しくても、スイッチのMACアドレステーブルが不適切なら正常に転送できない場合があります。

反対に、スイッチのMACアドレステーブルが正しくても、PC-AのARPキャッシュに偽のMACアドレスが登録されていれば、PC-Aは誤ったMACアドレス宛てのフレームを作成します。

この後者の問題を悪用するのが、ARP Spoofingです。

比較項目 ARPキャッシュ MACアドレステーブル
主な保持者 PC・サーバ・ルータ L2スイッチ
管理内容 IPv4 → MAC MAC・VLAN → ポート
主な学習方法 ARPのやり取りなど 受信フレームの送信元MAC
関連する攻撃 ARP Spoofing MAC Flooding
典型的な影響 誤ったMAC宛てに送信 転送先の誤りやフラッディング

6. ARP Spoofing（ARP偽装）とは何か

ここからセキュリティ上の中心論点に入ります。ARP Spoofingは、偽のARP情報を使って、端末のIPアドレスとMACアドレスの対応関係を誤認させる攻撃です。

ARP Poisoning（ARPキャッシュポイズニング）とも呼ばれます。

6-1. ARPにはどのような弱点があるのか

ARPは、もともと信頼できるLAN内でアドレス解決することを想定した仕組みです。

通常のARPには、受信したARP情報が本当にそのIPアドレスを持つ機器から送られたものか、暗号学的に認証する仕組みがありません。

例えば、PC-Aが次の情報を受信したとします。

192.168.1.1 のMACアドレスは
02:00:00:00:00:EE です

本来、192.168.1.1 はデフォルトゲートウェイのIPアドレスです。しかし、ARP情報の内容を偽装できる攻撃者が、実際には自分のMACアドレス 02:00:00:00:00:EE を通知することがあります。

PC-Aがその情報を受け入れてARPキャッシュを更新すると、次のようになります。

IPアドレス 本来のMAC 偽装後に記録されたMAC
192.168.1.1 02:00:00:00:00:01 02:00:00:00:00:EE

この状態では、PC-Aがデフォルトゲートウェイへ送るつもりで作成したEthernetフレームが、攻撃者のMACアドレス宛てになります。

6-2. なぜ偽装が成立するのか

ARPでは、送信者が通知するIPアドレスとMACアドレスの組合せが正しいことを、通常のプロトコルだけでは十分に検証できません。

そのため、攻撃者が偽のARP Replyなどを送り、被害端末がその情報を受け入れると、ARPキャッシュの内容が汚染されます。

ただし、すべてのOSがあらゆるARP応答を無条件に受け入れるわけではありません。未要求のARP応答を受け入れるか、既存エントリを上書きするかなどはOSや設定によって異なります。

したがって、偽のARP情報を送信しただけで、必ず攻撃が成功するわけではありません。

SC試験では、問題文に「端末が偽のARP応答を受信してキャッシュを更新した」といった条件があれば、その結果を正確に追跡することが重要です。

7. ARP Spoofingによる中間者攻撃の流れ

具体的な攻撃を追跡してみましょう。

7-1. ネットワーク構成

機器 IPアドレス MACアドレス
PC-A（被害端末） 192.168.1.10 02:00:00:00:00:0A
ルータ 192.168.1.1 02:00:00:00:00:01
攻撃者PC 192.168.1.50 02:00:00:00:00:EE

3台は同じVLAN内に存在するとします。PC-Aは、インターネットへ通信するとき、デフォルトゲートウェイ 192.168.1.1 を利用します。

7-2. 正常時

正常時のPC-AのARPキャッシュは次のとおりです。

192.168.1.1 → 02:00:00:00:00:01

そのため、外部へ送信するフレームは、ルータのMACアドレス宛てになります。

PC-A → ルータ → インターネット

7-3. 攻撃者が偽のARP情報を送る

攻撃者は、PC-Aに対して次のような偽情報を通知します。

192.168.1.1 のMACアドレスは
02:00:00:00:00:EE である

ここで偽装しているのは、ルータのIPアドレスに対応するMACアドレスです。

攻撃者自身のIPアドレス 192.168.1.50 を知らせたいわけではありません。PC-Aに「ルータのMACアドレスは攻撃者のMACアドレスだ」と思わせることが目的です。

7-4. PC-AのARPキャッシュが汚染される

PC-Aが偽情報を受け入れると、次のように変わります。

攻撃前：
192.168.1.1 → 02:00:00:00:00:01

攻撃後：
192.168.1.1 → 02:00:00:00:00:EE

これにより、PC-Aがルータへ送るつもりのフレームは、攻撃者のMACアドレスを宛先として作成されます。

7-5. 攻撃者が通信経路上に入る

攻撃者が受信したパケットを正規のルータへ転送するように動作していれば、次の通信経路が成立する場合があります。

PC-A（被害端末） → 攻撃者（通信を中継） → ルータ（正規のGW）

往復通信を中継するには、戻り方向の経路も攻撃者へ誘導するなど、追加の条件が必要です。

攻撃者がPC-Aからルータへの通信だけを誘導した場合、少なくともその方向の通信を受信する可能性があります。

双方向の通信を継続的に中継するには、ルータ側のARP情報も偽装する、あるいは別の方法で戻り方向の通信を確保する必要があります。

7-6. 攻撃者は何ができるのか

通信が攻撃者を経由する状態になれば、条件に応じて次のような行為が可能になります。

行為 内容
盗聴 通過するパケットを観測する
改ざん 保護されていない通信の内容を変更する
妨害 パケットを転送せず破棄する
誘導 通信内容や宛先への到達を操作する

ただし、ARP Spoofingに成功したことと、HTTPS通信の内容を復号できることは別です。 次の節で、この点を詳しく扱います。

8. ARP SpoofingとHTTPSの関係

8-1. 通信経路を乗っ取っても、暗号化が消えるわけではない

例えば、PC-AがHTTPSでWebサイトにアクセスしているとします。

ARP Spoofingによって攻撃者が通信経路上に入ったとしても、正常に確立されたTLS通信は暗号化されています。

そのため、攻撃者は通信パケットを取得できても、適切に保護されたTLSのアプリケーションデータを、通常はそのまま平文で読むことはできません。

ここでは、二つのセキュリティ対策が異なる層で働いています。

対象 仕組み 役割
LAN内の転送 ARP IPv4アドレスからMACアドレスを解決する
Web通信の保護 TLS 通信内容の暗号化、通信相手の認証、完全性の保護

ARPの弱点を利用してL2の通信経路を操作できても、TLSの暗号化や証明書検証を自動的に突破できるわけではありません。

8-2. TLS証明書検証の重要性

攻撃者が偽のWebサーバを提示した場合でも、クライアントがサーバ証明書を適切に検証していれば、不正な証明書によるなりすましを検出できます。

逆に、利用者が証明書警告を無視したり、端末が不正な認証局を信頼していたりすると、別の問題が発生する可能性があります。

つまり、ARP Spoofingへの防御とTLSによる保護は、互いに代替するものではありません。

L2の通信経路を守る対策と、アプリケーション通信を暗号化・認証する対策を組み合わせることが重要です。

8-3. 科目Bでの書き分け

例えば、設問で「ARP SpoofingによってHTTPS通信の内容を盗聴できるか」と問われた場合、単に「できる」「できない」と断定するのは不十分です。

答案では次のように条件を分けます。

ARP Spoofingによって通信経路上のパケットを取得できる場合があるが、TLSが正常に確立されていれば、暗号化されたアプリケーションデータをそのまま平文で読み取ることはできない。

このように、パケットを取得できることと、内容を解読できることを区別するのがポイントです。

9. ARP Spoofingへの防御策

攻撃の原因は、ARPで通知されるIPアドレスとMACアドレスの対応関係を十分に認証できないことでした。

したがって、防御策は「不正なARP情報を受け入れない」「不正な端末を接続させない」「攻撃の影響を検知する」という方向になります。

9-1. Dynamic ARP Inspection（DAI）

DAIは、スイッチがARPパケットを検査し、不正なIPアドレスとMACアドレスの組合せを含むARPパケットを破棄するための機能です。

例えば、ネットワークで正規の対応関係が次のように分かっているとします。

192.168.1.1 → 02:00:00:00:00:01

攻撃者が次の情報を含むARPパケットを送信した場合、

192.168.1.1 → 02:00:00:00:00:EE

スイッチが正規の対応関係と照合できれば、不正なARPパケットを破棄できます。

DAIでは、DHCP Snoopingによって作成したIPアドレスとMACアドレスなどの対応情報を利用する構成が代表的です。

ただし、固定IPアドレスの機器については、別途、適切な検証情報を登録する必要がある場合があります。

DAIを有効にするだけで、あらゆるARP偽装が無条件に防止されるわけではありません。 検証情報の正確性と信頼するポートの設定が重要です。

9-2. 静的ARPエントリ

重要な通信相手について、IPアドレスとMACアドレスの対応関係を固定する方法です。

例えば、PC-Aに次の対応を固定します。

192.168.1.1 → 02:00:00:00:00:01

適切に固定されていれば、偽のARP情報によってこの対応関係が変更されるリスクを減らせます。

ただし、機器の交換などでMACアドレスが変わった場合、管理者が設定を更新する必要があります。そのため、大規模なネットワークでは運用負担が大きくなることがあります。

9-3. IEEE 802.1X認証

802.1Xは、ネットワークへの接続時に認証を行う仕組みです。不正な端末が社内LANへ自由に接続することを防ぐために役立ちます。

ただし、802.1Xで認証された端末が侵害され、ARP Spoofingを行う場合も考えられます。

したがって、802.1Xは接続制御として有効ですが、ARPパケットの正当性を直接検証するDAIとは役割が異なります。

9-4. VLANによる通信範囲の分離

ARP Requestのブロードキャストは、通常、同じVLAN内に届きます。そのため、利用者や端末の用途に応じてVLANを分離すれば、ARPを利用した攻撃の到達範囲を制限できます。

ただし、同じVLAN内に攻撃者が存在する場合は、VLAN分離だけではARP Spoofingを防げません。

9-5. ARP監視・異常検知

ARPテーブルの変化や、ネットワーク内のARP通信を監視することも有効です。

例えば、デフォルトゲートウェイのIPアドレスに対応するMACアドレスが突然変わった場合、確認が必要です。

ただし、ルータの交換や冗長化構成の切替えでもMACアドレスが変化する場合があります。したがって、MACアドレスが変化したという事実だけで、直ちに攻撃と断定してはいけません。

9-6. 対策を比較する

対策 主な目的 注意点
DAI 不正なARP情報を検査・破棄 正しい対応情報が必要
静的ARP 重要なIPとMACの対応を固定 変更管理の負担
802.1X 不正端末のネットワーク接続を制限 認証済み端末の攻撃は別途対策
VLAN分離 攻撃の到達範囲を制限 同一VLAN内の攻撃は防げない
ARP監視 異常な対応関係の変化を検知 正常な変更との区別が必要

科目Bで「ARP Spoofingへの直接的な防御策」を問われた場合は、問題文の環境に応じて、DAIによるARPパケットの検証や、静的ARPエントリによる対応関係の固定を検討してください。

10. Gratuitous ARPとは何か

B：理解補助

Gratuitous ARPは、自分自身のIPv4アドレスに関するARP情報を、同じネットワーク内へ通知したり、アドレス重複を確認したりするために利用されるARPです。

通常のARP Requestは、他の機器のMACアドレスを調べるために送信します。一方、Gratuitous ARPでは、自分自身のIPアドレスを対象とするARP情報を送信します。

10-1. どのような場面で使われるか

例えば、次のような場面があります。

  • IPアドレスの重複を検出する。
  • IPアドレスとMACアドレスの対応関係を周囲に通知する。
  • 冗長化された機器が切り替わったとき、新しい転送先の情報を周囲へ知らせる。

Gratuitous ARPは正常なネットワーク運用でも使用されます。したがって、Gratuitous ARPを検出しただけで攻撃と判断してはいけません。

10-2. ARP Spoofingとの関係

ARP Spoofingでは、攻撃者がARP情報を偽装して送信することがあります。

しかし、Gratuitous ARPそのものが攻撃なのではありません。

正常なARP通知と、攻撃者による偽のARP通知を区別するには、IPアドレスとMACアドレスの正当な対応関係、ネットワーク構成、発生時刻などを確認する必要があります。

11. ARPテーブルと通信ログを読む

ここでは、実際の試験問題を意識して、ログから攻撃の可能性を判断します。

11-1. 正常時のARPテーブル

PC-AのARPキャッシュに次の情報があるとします。

IP Address       MAC Address
192.168.1.1      02:00:00:00:00:01
192.168.1.20     02:00:00:00:00:0B

192.168.1.1 は正規のデフォルトゲートウェイです。この状態では、PC-Aは外部ネットワーク宛てのフレームを、正規のルータのMACアドレスへ送信します。

11-2. 異常発生時

しばらくして、次のように変化しました。

IP Address       MAC Address
192.168.1.1      02:00:00:00:00:EE
192.168.1.20     02:00:00:00:00:0B

デフォルトゲートウェイのIPアドレスに対応するMACアドレスが、02:00:00:00:00:01 から 02:00:00:00:00:EE へ変わっています。

同時刻に、次のようなARPパケットが観測されたとします。

10:15:01 ARP Reply
Sender IP  : 192.168.1.1
Sender MAC : 02:00:00:00:00:EE

10:15:03 ARP Reply
Sender IP  : 192.168.1.1
Sender MAC : 02:00:00:00:00:EE

11-3. 何が疑われるか

このログからは、次の事実を確認できます。

  1. デフォルトゲートウェイのIPアドレスに対するMACアドレスの対応が変化した。
  2. 変更後のMACアドレスを通知するARP Replyが観測された。
  3. PC-Aがその対応関係をARPキャッシュに保持している。

この状況では、ARP Spoofingを疑うことができます。ただし、正規のルータ交換や冗長化の切替えなどによってMACアドレスが変わった可能性もあります。

11-4. 追加調査のポイント

実際に攻撃が発生したか確認するには、次の情報が役立ちます。

確認項目 調査目的
正規ルータのMACアドレス 偽装の有無を確認する
02:00:00:00:00:EE の接続ポート 不審な機器の接続場所を調べる
ARP Replyの送信元 誰が偽の対応関係を通知したか調べる
ルータの交換・切替え履歴 正常な変更の可能性を確認する
パケットキャプチャ 実際の通信経路を確認する
DAIの違反ログ 不正なARPパケットの検出状況を確認する

特に、ARPキャッシュに不正なMACアドレスが登録されていることと、攻撃者が実際に通信内容を取得したことは別の事実です。

調査や答案では、観測された事実と、そこから推測される攻撃を分けて説明してください。

12. 第10講のMAC Floodingとの比較

第10講で学んだMAC Floodingと、今回のARP Spoofingは混同しやすい攻撃です。

どちらもL2ネットワークに関係し、通信を不正に取得する機会を生み出す可能性があります。しかし、攻撃対象となる情報が異なります。

比較 MAC Flooding ARP Spoofing
攻撃対象 L2スイッチのMACアドレス学習 端末などのARPキャッシュ
悪用する仕組み 送信元MACアドレスの学習 IPとMACの対応関係の通知
主な攻撃方法 大量の異なる送信元MACを使う 偽のARP情報を通知する
典型的な影響 学習資源の逼迫、未知ユニキャストの増加など 誤ったMAC宛てへの送信、通信経路の誘導
直接的な対策例 Port Security DAI、静的ARP

例えば、問題文に次の記述があるとします。

「一つのスイッチポートで、短時間に数千個のMACアドレスが学習された」

この場合はMAC Floodingを疑います。

一方、次の記述があるとします。

「デフォルトゲートウェイのIPアドレスに対応するMACアドレスが、攻撃者のMACアドレスに変更された」

この場合はARP Spoofingを疑います。

MAC FloodingはMACアドレス学習の悪用、ARP SpoofingはIPとMACの対応関係の偽装と整理してください。

13. 科目Aの典型論点

13-1. ARPの役割

ARPは、IPv4アドレスに対応するMACアドレスを解決するプロトコルです。DNSのようにホスト名からIPアドレスを調べるものではありません。

13-2. ARP Requestの送信方法

通常のARP Requestは、宛先MACアドレス FF:FF:FF:FF:FF:FF のブロードキャストフレームで送信します。

13-3. ARP Replyの送信方法

通常のARP Replyは、問い合わせ元へのユニキャストで返されます。

13-4. 別ネットワークへの通信

宛先が別ネットワークの場合、ARPで解決するのは、通常、次にフレームを渡すデフォルトゲートウェイのIPアドレスです。

13-5. ARPキャッシュとMACアドレステーブル

ARPキャッシュはIPv4アドレスとMACアドレスの対応を管理します。スイッチのMACアドレステーブルは、MACアドレスとポートの対応を管理します。

13-6. ARP Spoofing

偽のARP情報によってIPアドレスとMACアドレスの対応関係を誤認させ、通信を攻撃者へ誘導する攻撃です。

13-7. IPv6との違い

ARPはIPv4で使用されます。IPv6では、ARPの代わりにICMPv6を利用した近隣探索（Neighbor Discovery）が使われます。

14. 科目Bの答案作成ポイント

科目Bでは、「ARPを悪用した攻撃」とだけ答えるのではなく、どの対応関係が、どのように偽装され、どの通信に影響したのかを説明する必要があります。

14-1. 設問例①：ARPの処理手順

設問

PC-Aが同じLAN内のPC-Bへ初めてIPv4パケットを送信する。PC-AのARPキャッシュにはPC-Bの情報がない。送信までの処理を説明せよ。

答案例

「PC-AはPC-BのIPアドレスを対象とするARP Requestをブロードキャストし、PC-BからのARP ReplyでMACアドレスを取得して、そのMACアドレス宛てにEthernetフレームを送信する。」

解説

重要なのは、次の四つを含めることです。

  • 問い合わせ対象はPC-BのIPアドレス。
  • ARP Requestはブロードキャスト。
  • PC-BからARP Replyが返る。
  • 取得したMACアドレスを使ってフレームを送信する。

14-2. 設問例②：別ネットワークへのARP

設問

PC-AのIPアドレスは 192.168.1.10/24、デフォルトゲートウェイは 192.168.1.1 である。PC-Aが 203.0.113.80 に通信するとき、ARPで解決するIPアドレスを答えよ。

答案例

192.168.1.1

解説

別ネットワーク宛てのパケットは、まずデフォルトゲートウェイへ渡します。したがって、ARPで解決する対象はデフォルトゲートウェイのIPアドレスです。

14-3. 設問例③：ARP Spoofingの目的

設問

攻撃者が、デフォルトゲートウェイのIPアドレスと攻撃者のMACアドレスを対応付けた偽のARP情報をPC-Aへ送る目的を説明せよ。

答案例

「PC-AのARPキャッシュに、デフォルトゲートウェイのMACアドレスとして攻撃者のMACアドレスを登録させ、ルータ宛ての通信を攻撃者へ誘導するため。」

解説

単に「盗聴するため」と書くより、ARPキャッシュの変更とフレームの転送先を明示する方が正確です。

14-4. 設問例④：ARP Spoofingへの対策

設問

スイッチ側でARP Spoofingを防止するための対策を一つ挙げ、その仕組みを説明せよ。

答案例

「Dynamic ARP Inspectionを導入し、ARPパケットに含まれるIPアドレスとMACアドレスの対応を正規の情報と照合して、不正なARPパケットを破棄する。」

解説

対策名だけでなく、何を検査し、何を防止するのかまで説明します。

14-5. 設問例⑤：HTTPSへの影響

設問

ARP Spoofingによって攻撃者がHTTPS通信の経路上に入った場合でも、通信内容を直ちに平文で読み取れるとは限らない理由を説明せよ。

答案例

「HTTPSではTLSによって通信内容が暗号化されており、通信経路上でパケットを取得しても、正常に保護されたアプリケーションデータをそのまま復号できないため。」

解説

ARPによる経路制御とTLSによる暗号化は異なる仕組みです。

15. 重要事項の整理

今回の講義で最も重要なのは、次の六つです。

第一に、ARPはIPv4アドレスからMACアドレスを解決する仕組みです。 Ethernetフレームを作成するために必要な情報を取得します。

第二に、ARP Requestは通常ブロードキャスト、ARP Replyは通常ユニキャストです。 ARPキャッシュに必要な情報がないとき、問い合わせと応答によってMACアドレスを取得します。

第三に、別ネットワーク宛てでは、通常、デフォルトゲートウェイのMACアドレスをARPで解決します。 最終宛先IPアドレスとEthernetの宛先MACアドレスは一致する対象を示すとは限りません。

第四に、ARPキャッシュとスイッチのMACアドレステーブルは別物です。 前者はIPとMAC、後者はMACとポートの対応を管理します。

第五に、ARP Spoofingは偽のARP情報によって通信経路を誘導する攻撃です。 デフォルトゲートウェイのIPアドレスに攻撃者のMACアドレスを対応付けさせることが典型例です。

第六に、ARP SpoofingとTLSの暗号化は異なる層の問題です。 経路上でパケットを取得できても、HTTPS通信の内容を直ちに平文で読めるわけではありません。

これらは必要な講義で扱い、今回はARPの通信手順、偽装の成立過程、攻撃と防御の対応関係を優先します。
