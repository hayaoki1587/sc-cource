2. 無線LANの基本構成【A：必須】

2-1. 無線LANとは

有線LANでは、PCとスイッチをLANケーブルで接続します。一方、無線LANでは電波を使ってデータを送受信します。

一般的なオフィスの無線LANでは、端末はアクセスポイント（AP：Access Point）を経由して社内ネットワークに接続します。

インフラストラクチャモードの概念図。端末からAPまでは無線、APから社内ネットワーク側は有線の例。

例えば、ノートPCが社内のファイルサーバへアクセスする場合、次のように通信します。

  1. PCが周囲の無線LANを検出する。
  2. 接続するAPを選び、必要な認証・鍵確立を行う。
  3. PCからAPへ無線フレームを送信する。
  4. APが有線LAN側へ通信を中継する。
  5. 社内ネットワークを経由してファイルサーバに届く。

APは、無線LANと有線LANをつなぐ役割を持ちます。ただし、APがルータやファイアウォールの機能まで持つかどうかは機器・構成によって異なります。

2-2. インフラストラクチャモードとアドホックモード

方式仕組み代表的な利用
インフラストラクチャAPを介して通信する企業・家庭のWi-Fi
アドホック端末同士が直接通信する一時的な端末間接続

参考書では両方式が紹介されています。試験対策では、まず企業ネットワークで一般的なインフラストラクチャモードを理解してください。

2-3. SSIDとBSSID

SSID（Service Set Identifier）は、無線LANネットワークを識別する名前です。例えば Company-WiFi という名称が該当します。

ここで注意したいのは、SSIDがAPそのものの固有識別子ではないことです。同じ Company-WiFi というSSIDを複数のAPに設定できます。これにより、オフィス内を移動したときにも同じ無線LANを継続利用できます。

一方、BSSID は基本サービスセットを識別する値で、通常はAPの無線インタフェースに関連付けられたMACアドレス形式の識別子です。

項目SSIDBSSID
役割無線ネットワークの名前基本サービスセットの識別
例Company-WiFi02:11:22:33:44:55
複数APで同じ値可能通常は異なる
セキュリティ上の注意知っているだけでは本人認証にならない偽装される可能性がある

SSIDを知っていることと、接続する権限があることは別です。

3. 無線LANの通信制御：CSMA/CA【A：必須】

3-1. なぜ通信の順番を制御するのか

無線LANでは、同じチャネルを使う複数の端末が電波という共有媒体を利用します。例えば、PC-AとPC-Bが同時に送信すると、APが通信を正しく受信できないことがあります。

有線Ethernetで歴史的に使われたCSMA/CDは、衝突を検出して再送する方式です。しかし、無線LANでは自分が送信している最中に、他端末からの衝突を確実に検出することが難しくなります。

そこで無線LANでは、CSMA/CA（Carrier Sense Multiple Access with Collision Avoidance） を基本とする仕組みを使います。CAはCollision Avoidance、つまり「衝突回避」です。

3-2. CSMA/CAの動作

CSMA/CAの簡略化した送信の流れ

  1. 端末は、送信前にチャネルが使用中か確認します。
  2. 空いていれば、定められた待機時間を置きます。
  3. 複数端末が同時に送信しないよう、ランダムなバックオフ時間を利用します。
  4. バックオフが終了した端末がデータを送信します。
  5. ユニキャスト通信では、通常、受信側からのACKで正常受信を確認します。ACKが得られなければ再送が行われることがあります。

ランダムな待機時間を使うのは、複数端末が同じタイミングで再送する可能性を下げるためです。

CSMA/CAは衝突を完全になくす技術ではありません。 衝突の発生確率を減らす技術です。

3-3. 隠れ端末問題【A：必須】

AとBは互いの電波を検知できないが、両方ともAPとは通信できる。

端末Aと端末Bは、どちらもAPに電波が届きます。しかし、端末同士は離れているため、相手の電波を検知できません。

その結果、Aが送信中でもBはチャネルが空いていると判断し、送信してしまうことがあります。AP付近で信号が重なり、受信に失敗する可能性があります。これが隠れ端末問題です。

対策の一つが RTS/CTS です。

  • RTS（Request To Send）：端末が送信したいことをAPへ通知する。
  • CTS（Clear To Send）：APが送信可能であることを通知する。
  • CTSを受け取った他の端末は、指定された期間の送信を控える。

これにより、隠れ端末による衝突を減らせます。ただし、制御フレームの分だけ通信のオーバーヘッドが増えます。

4. IEEE 802.11と周波数帯【B：理解補助】

無線LANの代表的な規格を整理します。

規格Wi-Fi世代主な周波数帯
IEEE 802.11nWi-Fi 42.4GHz / 5GHz
IEEE 802.11acWi-Fi 55GHz
IEEE 802.11axWi-Fi 6 / 6E2.4GHz / 5GHz、6Eでは6GHz
IEEE 802.11beWi-Fi 72.4GHz / 5GHz / 6GHz

参考書pp.195〜196にはWi-Fi 6Eまでの説明があります。Wi-Fi 7は講師補足です。利用できる周波数帯は国・地域の制度や機器の対応状況にも依存します。

一般に、2.4GHz帯は障害物の影響を受けにくい傾向がある一方、Bluetoothなどとの干渉が問題になることがあります。5GHz帯や6GHz帯は利用可能なチャネルの選択肢が増えますが、電波の到達範囲や障害物の影響を考慮する必要があります。

SC試験では、規格ごとの最大速度をすべて暗記するより、周波数帯、電波干渉、通信の安定性、セキュリティの関係を理解することを優先します。

5. 無線LANの認証と暗号化【A：必須】

無線LANでは、電波が壁の外まで届く可能性があります。つまり、社内LANケーブルに物理的に接続していない攻撃者でも、無線通信を受信できる場合があります。

そのため、無線LANでは特に次の3つを区別します。

  • 認証：接続してよい利用者・端末か確認する。
  • 暗号化：無線区間の通信内容を第三者に読まれにくくする。
  • アクセス制御：接続後に利用できるネットワークやシステムを制限する。

5-1. WEP・WPA・WPA2・WPA3

方式主な仕組みセキュリティ上の判断
WEPRC4を利用脆弱であり使用しない
WPA主にTKIPを利用古く、使用を避ける
WPA2主にAES-CCMP適切な設定で利用可能
WPA3SAEや強化された暗号・認証方式など対応環境では優先して検討

WEPが危険な理由

WEPではRC4と短い初期化ベクトル（IV）を利用します。IVの再利用などを利用した攻撃が成立し、通信から鍵を推定される危険があります。

そのため、単に「WEPの鍵を長くする」だけでは本質的な問題を解決できません。

WPA2の特徴

WPA2ではAES-CCMPが代表的な暗号化方式です。

ただし、WPA2だから必ず安全というわけではありません。例えば、推測しやすい事前共有パスワードを使用すると、攻撃者にパスワードを推測されるリスクがあります。

WPA3の特徴

WPA3-PersonalではSAE（Simultaneous Authentication of Equals）を用います。

SAEは、従来のWPA2-PersonalのPSKを利用した4-way handshakeに対するオフライン辞書攻撃の問題を改善する仕組みです。

ただし、WPA3でも弱いパスワードの利用や実装上の脆弱性など、あらゆるリスクがなくなるわけではありません。

5-2. Personal方式とEnterprise方式

ここは科目Bで重要な構成判断につながります。

Personal方式は、家庭用Wi-Fiなどで複数の利用者が共通のWi-Fiパスワードを使う方式です。

例えば、社員全員に同じWi-Fiパスワードを知らせている会社を考えます。退職者がパスワードを知ったままなら、退職後も電波の届く場所から接続を試みることができます。共通パスワードを変更すると、ほかの社員の端末にも再設定が必要になる場合があります。

Enterprise方式では、IEEE 802.1XとRADIUSサーバなどを組み合わせ、利用者・端末ごとに認証できます。

例えば、社員Aのアカウントを無効化しても、社員Bの認証情報を変更する必要はありません。

IEEE 802.1Xの基本構成。端末の認証情報をAPが中継し、RADIUSサーバが認証を判断する。

構成要素役割
サプリカント認証を要求する端末側
オーセンティケータ認証を中継し、接続を制御するAPなど
認証サーバ認証情報を検証するRADIUSサーバなど

重要：APとRADIUSサーバは同じ役割ではありません。 APは認証要求を中継してネットワークアクセスを制御し、RADIUSサーバは認証を判断します。

5-3. EAP-TLS

EAP-TLSは、IEEE 802.1Xの認証で使用できる方式の一つです。

一般に、クライアント証明書とサーバ証明書を利用して相互認証します。これにより、社員が共通のWi-Fiパスワードを覚えて使い回す構成を避けられます。

ただし、証明書の発行・配布・失効管理が必要です。また、端末が接続先サーバの証明書を適切に検証しなければ、偽の認証サーバに誘導されるリスクが残ります。

6. 無線LANに対する代表的な攻撃【A：必須】

6-1. 盗聴

攻撃者が無線区間の電波を受信し、通信内容を取得しようとする攻撃です。

対策は、適切な無線LAN暗号化と、必要に応じたHTTPSなどのエンドツーエンド暗号化です。

無線LANが暗号化されていても、APから先の通信まで自動的に暗号化されるとは限りません。第28講のVPNと同じく、どの区間が保護されているかを考えます。

6-2. 偽アクセスポイント（Evil Twin）

攻撃者が、正規APと同じSSIDを持つ偽のAPを用意する攻撃です。

例えば、正規SSIDが Company-WiFi の場合、攻撃者も同じSSIDで電波を発信できます。端末が偽APに接続すると、攻撃者が通信を中継したり、偽のログイン画面へ誘導したりする危険があります。

SSIDが一致するだけでは、正規APである証明になりません。

対策として、Enterprise方式での適切なサーバ証明書検証、端末の接続設定管理、不正APの検知などが挙げられます。

6-3. 不正APの設置

社員が許可なく市販の無線LANルータを社内LANへ接続した場合を考えます。

そのAPの認証や暗号化が弱ければ、攻撃者が社外から接続して社内LANへ侵入する経路になる可能性があります。

この場合、正規APの設定だけを強化しても対策として不十分です。有線LAN側での接続制御、不正AP検知、物理的な機器管理などが必要です。

6-4. 認証解除フレームの悪用

無線LANには、端末の接続解除に関係する管理フレームがあります。

これらが適切に保護されていない構成では、攻撃者が管理フレームを偽装して端末の接続を妨害することがあります。

対策として、PMF（Protected Management Frames）などの管理フレーム保護があります。ただし、PMFも無線妨害電波そのものを防ぐ技術ではありません。

7. SSIDステルス・MACフィルタリングの限界【A：必須】

参考書ではSSIDステルスやMACアドレスフィルタリングが紹介されています。しかし、これらを強力な認証・暗号化の代わりと考えてはいけません。

SSIDステルス

SSIDを通常のビーコンで通知しない設定です。

しかし、無線通信のほかの管理フレームなどからSSIDを推測・取得できる場合があります。

そのため、SSIDを隠すだけで不正接続や盗聴を防げるわけではありません。

MACアドレスフィルタリング

許可されたMACアドレスを持つ端末だけに接続を許す方式です。

ただし、MACアドレスは通信から観測されることがあり、攻撃者が偽装できる場合があります。

したがって、MACアドレスフィルタリングだけで端末の正当性を保証することはできません。試験で「MACアドレスを登録したので、なりすましは不可能である」という選択肢があれば、誤りです。

プライバシーセパレータ

プライバシーセパレータ（APアイソレーション）は、同じAPに接続している無線端末同士の直接通信を制限する機能です。

例えば、来客用Wi-Fiに接続した利用者Aが、同じWi-Fiに接続した利用者Bの端末へアクセスすることを防ぐ目的で使います。

ただし、ゲスト端末から社内サーバへの通信まで必ず遮断するわけではありません。社内LANへのアクセス制御は、VLANやFWなどで別途設定します。

8. SSIDとVLANを組み合わせたネットワーク分離【A：必須】

第27講のVLANと直接つながる内容です。例えば、会社で次のような無線LANを提供するとします。

SSIDVLAN利用者
Corp-WiFiVLAN 10社員
Guest-WiFiVLAN 20来客
Device-WiFiVLAN 30業務用端末

一台のAPから複数のSSIDを提供し、それぞれを異なるVLANに対応付けることができます。

SSIDごとにVLANを割り当てる構成例

しかし、ここで重要な点があります。

VLANを分けただけでは、VLAN間の通信が絶対にできなくなるわけではありません。

L3スイッチやルータでVLAN間ルーティングが有効になっていれば、設定次第で通信できます。

来客用Wi-Fiから社員用サーバへの通信を防ぎたい場合は、FWやACLなどで明示的に遮断する必要があります。例えば、次のような方針です。

Guest VLAN 20 → Internet      ALLOW
Guest VLAN 20 → Corp VLAN 10  DENY
Guest VLAN 20 → Mgmt VLAN 99  DENY

これは設定方針を示す概念例であり、特定製品の設定コマンドではありません。

9. 設定・ログを読む【A：必須】

事例1：退職者がWi-Fiへ接続できる

会社では全社員が同じWPA2-Personalのパスワードを利用しています。退職した社員がそのパスワードを知っており、退職後も変更されていません。

問題点：退職者が引き続きWi-Fiへの接続を試みることができます。個人単位でアクセス権を無効化しにくい構成です。

対策：IEEE 802.1Xを使ったEnterprise方式などへ移行し、利用者・端末単位で認証を管理します。共通パスワード方式を継続するなら、漏えい・退職時の鍵変更と配布管理が必要です。

事例2：RADIUS認証に失敗する

以下は説明用の簡略ログです。

10:20:01 AP=AP-01
SSID=Corp-WiFi
CLIENT=02:AA:BB:CC:DD:01
AUTH_METHOD=EAP-TLS
RESULT=REJECT
REASON=CLIENT_CERT_EXPIRED

このログから、EAP-TLSで使用するクライアント証明書の有効期限切れが原因で認証を拒否されたと判断できます。

確認対象は、端末証明書の有効期限、更新状況、証明書配布手順などです。

ここで「無線LANの暗号化方式が弱いことが原因」と答えるのは不適切です。ログが示しているのは認証証明書の問題です。

事例3：来客用Wi-Fiから社内サーバへ通信できる

TIME=10:31:15
SSID=Guest-WiFi
SRC=192.168.20.51
DST=10.10.1.20
PROTO=TCP
DPORT=445
ACTION=ALLOW

このログは、来客用Wi-Fiの端末から社内サーバのTCP/445（SMB）への通信が許可されたことを示しています。

ただし、SMBの認証成功やファイルの閲覧成功まで証明するログではありません。

問題点：来客用ネットワークから社内サーバへの不要な通信が許可されている可能性があります。

対策：Guest VLANから社内LANへのアクセスをFW・ACLで拒否し、インターネット向けなど必要な通信だけを許可します。

科目Bの答案作成

例えば、次の問題を考えます。

来客用Wi-Fiに接続した端末から、社内の管理サーバへ通信できることが判明した。必要な対策を述べよ。

不十分な答案：「Wi-Fiのセキュリティを強化する。」

これでは、どの通信をどう制限するのか不明です。

改善した答案：「来客用SSIDに対応するVLANから管理サーバへの通信を遮断するため、FWまたはL3スイッチのACLで、必要な通信以外を拒否する。」

このように、通信元・通信先・制御する装置・制御内容を具体的に記述します。

11. 重要事項の整理

今回の中心は、次の因果関係です。

  1. 無線LANは電波を共有するため、CSMA/CAなどの通信制御が必要になる。
  2. 電波は第三者にも受信され得るため、認証と暗号化が重要になる。
  3. SSIDやMACアドレスだけでは、利用者・端末の正当性を十分に保証できない。
  4. WPA2/WPA3で無線区間を保護しても、接続後の社内アクセス権限は別問題である。
  5. 社員用・来客用などのSSIDをVLANと対応付け、FWやACLで通信を制限する。

C：任意の発展学習として、MIMO・MU-MIMO・OFDMAの詳細、802.11k/v/rによるローミング最適化、無線フレームの細かな構造などがあります。現段階では、これらより認証・暗号化・アクセス制御を優先してください。
